# VoC Lens

**라이브 대시보드: [voc-lens.streamlit.app](https://voc-lens.streamlit.app/)** — 합성 데이터 시연과 함께, **직접 분석** 화면에서 리뷰 CSV·상담 전사본(+WAV)·영상 자막을 올려 바로 분석할 수 있습니다.

포트폴리오 소개 페이지: [docs/index.html](docs/index.html) · PDF [docs/VoC-Lens_portfolio.pdf](docs/VoC-Lens_portfolio.pdf)

**VoC**(Voice of Customer, 고객의 소리) Lens는 리뷰, 상담 음성, 영상에서 고객의 감정을 추정하고, 그 결과를 **우선순위가 매겨진 CX 개선 과제**로 바꾸는 분석 도구입니다.

## 30초 요약

| | |
|---|---|
| 하는 일 | 리뷰, 상담 음성, 영상을 같은 지수 6개와 불만 분류 기준으로 분석하고, 무엇부터 고칠지 우선순위를 매깁니다. LLM 없이 규칙과 작은 학습 모델로 동작합니다 |
| 리뷰 (실제 데이터) | 네이버 쇼핑 리뷰 39,807건. 불만 탐지 정밀도 0.88(규칙), 재학습 분류기 F1 0.69. 상수 19개를 흔들어도 개선 과제 순위 Spearman 0.97 이상 |
| 음성 | 음향 규칙이 각성 높음·낮음을 AUC 0.88로 가릅니다(영어, 한국어 감정 음성 모두. 연기 음성이라 상한선) |
| 영상 | 실제 YouTube 6편에서 수집부터 분석까지 끝까지 돕니다(자막 없는 영상은 STT로) |

| 만든 것 | Python 패키지와 CLI, Streamlit 대시보드, 감정 모델과 불만 분류기 학습, 케이스 스터디 4건, 테스트 310개 |

자세한 수치는 [실제 데이터 평가](docs/evaluation.md), 남은 일정은 [구현 계획](docs/implementation_plan.md)에 있습니다.

## 왜 만들었나

- 감정 점수가 나와도 "그래서 무엇부터 고칠지"로 이어지지 않는 경우가 많습니다.
- 리뷰, 상담, 영상은 따로 분석되는 경우가 많아서, 한 채널에서만 보이는 불만인지 모든 채널에 걸친 문제인지 가리기 어렵습니다.
- 이 프로젝트는 세 채널을 **하나의 지수 체계와 불만 분류 기준**으로 분석하고, 결과를 영향도×난이도 매트릭스로 정리합니다.

## 검증 현황: 문제 정의 → 문제 해결 → 결과 검토

채널마다 검증된 정도가 다릅니다. **실제 데이터로 정확도를 잰 것은 리뷰뿐**이고, 상담과 영상은 막힌 조건 안에서 확인할 수 있는 것부터 확인한 단계입니다. 한계는 숨기지 않고 "어디까지 쓸 수 있는지"로 적었습니다. 채널별 자세한 수치는 [실제 데이터 평가](docs/evaluation.md)에 같은 구조로 있습니다.

### 리뷰

- **문제 정의**: 사전과 규칙으로 만든 불만 탐지와 지수가 실제 리뷰에서 얼마나 맞는지, 손으로 정한 상수에 결론이 흔들리는지 알아야 했습니다.
- **문제 해결**: 네이버 쇼핑 리뷰 39,807건과 라벨링 평가 세트 337절로 규칙 기준선과 학습 모델을 비교했습니다. 평가 세트를 만든 뒤에는 규칙을 고치지 않았고, 상수 19개를 0.5~1.5배로 흔들어 순위가 유지되는지 봤습니다. 실제 리뷰에서 찾은 CSAT 임계값 버그는 고치고 회귀 테스트를 넣었습니다.
- **결과 검토**: 불만 탐지 정밀도 0.88(재현율 0.32), 학습 모델 조합 F1 0.59, 만족 구분 AUC 0.86, 상수 민감도 Spearman 0.97 이상입니다. 다만 평가 세트 라벨은 Claude가 붙인 것입니다. 사람 검수 20절에서 불만 여부는 사람과 대체로 맞았지만(일치 0.90, κ 0.78) 유형은 12절 중 5절만 완전히 같아, 유형별 수치를 사람 기준 정확도로 읽는 것은 제한되고, 합성 데이터로 학습한 CSAT 모델은 만족 비율을 부풀리므로(실제 50% → 80.8%) 같은 데이터 안의 비교에만 씁니다.
- **보강 (직접 라벨 재학습)**: 0이던 성능, 오배송·누락, 효과 없음을 잡으려고 개발용 리뷰 915절에 Claude 라벨을 붙여 분류기를 다시 학습했습니다. 기준값은 개발용 정답에서만 골랐습니다(0.3). 평가 세트에서 불만 여부 F1은 0.59 → 0.69, 재현율은 0.55 → 0.82로 올랐고 정밀도는 0.64 → 0.60으로 내려갔습니다. 세 유형은 성능 1/7, 오배송·누락 2/4, 효과 없음 0/4입니다. 하지만 기존 모델도 기준값 0.3으로 낮추면 세 유형은 똑같이 나옵니다. 세 유형 개선은 기준값 효과이고, 직접 라벨의 효과로 말할 수 있는 것은 같은 기준값에서 정밀도 +0.09, 유형 micro F1 +0.07까지입니다. 세 유형의 정답이 4~7절뿐이고 이 평가 세트는 이미 여러 번 봤으므로, 이 개선을 일반화하는 것은 제한됩니다. 배포 화면은 그대로 규칙 v0.3.1입니다.
- **앞으로 추진**: 사람 검수를 30절 더 해 50절로 늘리고 유형 일치도를 다시 잽니다. 어긋난 사이즈·색상, 냄새, 다중 유형 절이 우선입니다. 50절에서도 유형 일치가 절반 아래면 유형 지표는 "Claude 기준"으로만 표기합니다. 평가용에서 새로 뽑은 338절에 사람 라벨을 붙여 재학습 모델을 한 번만 다시 평가하고, 약지도만으로 다시 학습한 모델과 비교해 직접 라벨 효과를 떼어 냅니다.

### 상담 (음성)

- **문제 정의**: 음성 톤이 텍스트가 놓치는 감정의 세기를 보완한다는 가정을 확인해야 하지만, 한국어 상담 음성(AI Hub)은 승인 전입니다.
- **문제 해결**: 같은 문장을 여러 감정으로 읽은 공개 감정 음성 두 가지(RAVDESS 1,440개, CREMA-D 7,442개)로 음향 각성 규칙을 평가했습니다. 가중치는 바꾸지 않았고, 두 번째 데이터로 재현성을 보고, 화자 기준선 세 가지와 특징 하나씩의 AUC로 원인을 진단했습니다. 상담 전사본은 합성 4건으로 대화 흐름이 도는지만 확인했습니다.
- **결과 검토**: 텍스트로는 가를 수 없는 각성 차이를 AUC 0.88 / 0.83으로 가릅니다(화자 정규화 전 0.82 / 0.81). 음성이 텍스트와 별개의 정보를 준다는 것은 두 번 확인했습니다. 하지만 연기한 영어 음성이라 이 수치는 상한선이며 실제 상담 성능 근거로 쓰는 것은 제한됩니다. 가중합 규칙은 가장 좋은 단일 특징보다 낮았고, 쉼 비율 가중치는 두 데이터 모두 부호가 반대였습니다. "음성이 텍스트보다 낫다"와 융합 가중치는 아직 설계 가정입니다 ([분석 설계서](docs/analysis_design.md)).
- **보강 (한국어 음성)**: 승인을 기다리는 동안 바로 받을 수 있는 한국어 감정 음성 두 가지(Hi,KIA 488개, Deeply 1,697개)로 같은 지표를 쟀습니다. 문장 단위인 Deeply에서 AUC 0.88로 영어와 비슷했고, 영어에서 못 잰 말 속도를 처음 검증했습니다(효과 −0.018~+0.039, 특징 하나만으로는 0.60~0.64로 약함). 0.6초짜리 클립이 대부분인 Hi,KIA에서는 1초 게이트 때문에 기준선이 흔들려 0.76에 그쳤습니다. 공개 상담 녹음은 찾지 못해 YouTube 상담 롤플레이 4편을 상담 파이프라인으로 돌렸고, 4편 모두 끝까지 돌았지만 해설 내레이터가 섞인 2편은 내레이터를 고객으로 잡았습니다. 롤플레이의 화자와 각성에는 정답이 없어 정확도 주장은 제한됩니다.
- **앞으로 추진**: AI Hub 승인 후 상담 음성을 개발용과 평가용으로 나눠, 개발용에서만 쉼 비율 부호와 가중치를 다시 정하고(v0.2) 평가용에서 v0.1과 비교합니다. 같은 통화에서 텍스트만 쓴 결과와 음성을 합친 결과를 비교해, 나아지지 않으면 융합 가중치를 낮춥니다. 그 전에 롤플레이 405발화에 사람 라벨을 붙여 화자 분리 오류율과 역할 정확도를 재고, 화자 수 자동 추정과 1초 미만 발화의 기준선 규칙을 개발용에서 정합니다.

### 영상

- **문제 정의**: 영상 파이프라인은 합성 번들로만 확인한 상태였습니다. 실제 YouTube URL에서 끝까지 도는지, 자막 없는 영상도 처리되는지 알아야 했습니다. 정답 라벨이 없어 정확도는 잴 수 없으므로 목표를 동작 점검으로 정했습니다.
- **문제 해결**: 실제 리뷰 영상 3편(수동 자막 2편 456문장, 자막 없는 1편은 STT 71문장, 댓글 966개)을 돌렸습니다. 그 과정에서 영상 밖 자막 큐, 413초짜리 문장, 도메인 설정 누락, 댓글 몰입 상한, ffmpeg 의존, PyAV와 pyannote 4.x 호환, 영상에서 음향 각성이 계산되지 않던 문제를 찾아 고쳤습니다. 모두 입력 처리 쪽이고 분류 규칙은 고치지 않았습니다.
- **결과 검토**: 세 편 모두 수집부터 분석까지 끝까지 돌고, 자막 없는 영상에도 STT, 화자 분리, 음향 각성이 붙습니다. 댓글 속성(성능, 가격)은 영상 내용과 맞아 보입니다. 하지만 크리에이터 문장 79~89%가 감성 0이고 내용 구간 분할은 쓸 수 없는 수준이라, 크리에이터 감성 곡선과 구간 분석은 사용이 제한됩니다. CPU에서는 영상 길이의 2.4배가 걸리고, STT 전사 정확도(CER)는 정답 전사본이 없어 재지 못했습니다.
- **보강 (말 감성, 구간 분할)**: 감정 모델을 자막에 붙이는 옵션과 시간 위치·제품군을 쓰는 구간 분할 v0.2를 넣고, 원칙 6개를 결과를 보기 전에 설정에 고정한 뒤 처음 보는 영상 3편에서 한 번만 쟀습니다. 도입이 중간에 나오거나 자동차에 언박싱이 붙는 문제는 사라졌지만, 같은 이름 구간을 합치면서 크리에이터 챕터 경계까지 지워 챕터 재현율이 5편 중 4편에서 떨어졌습니다. 감정 모델은 감성 0 비율을 0으로 만들었지만 모든 문장에 감정을 붙인 과잉 호출이고, 댓글은 음수로 쏠렸습니다. 그래서 기본값은 v0.1과 감정 사전으로 두었습니다. 위반 0건은 규칙이 정의상 보장하는 값이라 정확도 근거로 쓰는 것은 제한됩니다.
- **앞으로 추진**: 영상 6편 960문장에 사람 라벨(감성, 구간 경계)을 붙여 감정 사전과 모델, 구간 v0.1과 v0.2를 정확도로 비교합니다. 감정 모델은 개발용 라벨에서 중립 기준값을 고르고, 구간 병합은 경계를 지우지 않고 이름에만 적용합니다. 일부 구간을 사람이 받아 적어 CER을 재고, GPU와 작은 Whisper 모델로 처리 시간을 비교하고, 속성 추출에 도메인 필터를 넣습니다.

## 지수 6개

| 지수 | 의미 | 연결되는 CX 지표 |
|---|---|---|
| 스트레스 | 부정 + 높은 각성 (짜증, 분노) | — |
| 행복 | 긍정 (만족, 기쁨) | CSAT |
| 부정 정서 | 부정 + 낮은 각성 (실망, 체념). 의료 진단이 아님 | — |
| 좌절 | 문제를 해결하느라 애쓴 정도 (반복 문의, 대기) | CES |
| 감정 회복 | 부정 감정이 뒤에서 긍정으로 돌아섰는지 | 서비스 회복, FCR |
| 몰입 | 관심과 열의 (구체성, 재주문·추천 의사) | NPS 성향 |

모든 지수는 Valence(긍정–부정) × Arousal(각성) 모델을 바탕으로 합니다. 정의와 산식은 [PRD 7장](docs/PRD.md)과 [`indices/compute.py`](src/voclens/indices/compute.py)에 있습니다.

## 빠른 시작

```bash
python -m venv .venv
.venv/Scripts/activate          # macOS/Linux: source .venv/bin/activate
pip install -e ".[dev]"

voclens review data/samples/delivery_reviews_synthetic.csv
voclens report --out reports/review_report.md
voclens cx --out reports/cx_report.md
voclens call data/samples/calls
voclens video data/samples/videos
voclens query --list
voclens query complaint_share_by_brand
voclens query recovery_triggers
pytest
```

대시보드:

```bash
pip install -e ".[app]"
streamlit run app/streamlit_app.py
```

DB가 없으면 첫 실행 때 합성 샘플로 세 채널 분석과 CX 추정을 자동으로 합니다. DB 경로를 바꾸거나 샘플을 다시 분석하는 사이드바 기능은 `VOCLENS_DASHBOARD_ADMIN=1` 환경 변수를 켰을 때만 나타납니다 (공개 배포에서 방문자가 서버 경로를 고르거나 데이터를 지우지 못하게).

상담은 전사본 JSON을 읽습니다. 형식은 [상담 전사본 형식](docs/call_transcript_format.md)에 있습니다. 영상은 번들 JSON이나 YouTube URL을 받습니다. 형식은 [영상 입력 형식](docs/video_bundle_format.md)에 있습니다.

리뷰 CSV에는 `text` 열이 필요합니다. `rating`, `created_at`, `brand`, `store`, `owner_reply` 열은 있으면 씁니다. 열 이름은 [configs/default.yaml](configs/default.yaml)에서 바꿉니다.

| 3 | 온도·식감 | 11.1% | 35.0% (18.3%) | +24% | 2 | 핵심 과제 |

리포트에는 이 밖에 다음 내용이 들어갑니다.
- 브랜드 간 차이 검정 (카이제곱, Mann-Whitney U, 효과 크기)
- 고객 여정 단계별 감정, 속성별 감성
- 별점–감정 불일치 리뷰
- 리뷰 이벤트 편향 점검

## 상담 분석 흐름

```
전사본 JSON (+ 선택: WAV)
    → 화자 역할 판정 (인사 스크립트·정형 표현으로 상담원/고객 구분)
    → 대화 역학 (발화 점유율, 끼어들기, 침묵, 같은 말 반복, 공감·해결 표현, 통화 결과)
    → 발화 감정 (텍스트)
    → [WAV가 있으면] 피치·에너지·말 속도 → 화자 기준 z-score → 음성 각성 → 융합
    → 고객 발화의 불만 유형·CX 신호
    → 고객 발화만으로 지수 6개, 좌절 지수에 대화 역학 가산
    → 감정 급변 이벤트 + 직전 상담원 발화(회복 계기)
```

융합은 차원마다 가중치가 다릅니다. 각성은 음향 0.7 / 텍스트 0.3, 긍정·부정은 음향 0.3 / 텍스트 0.7입니다. 목소리는 흥분 정도를, 말의 내용은 좋고 나쁨을 더 잘 드러내기 때문입니다. 각 모달의 신뢰도(STT 신뢰도, SNR, 발화 길이)에 따라 가중치가 줄어듭니다.

합성 상담 4건의 결과입니다. 실제 상담이 아니며, 시나리오대로 나오는지 확인하는 용도입니다.

| 통화 | 결과 | 좌절 | 감정 회복 | Peak-End | 끼어들기 | 반복 |
|---|---|---|---|---|---|---|
| 누락 → 사과·재발송 | 해결 | 11.7 | 90.6 | 26.6 | 0 | 0 |
| 지연 → 반복 문의 | 보류 | 62.9 | 45.3 | 66.3 | 2 | 1 |
| 이물질 환불 | 이관 | 9.6 | 60.1 | 37.8 | 0 | 0 |
| 쿠폰 문의 | 해결 | 6.0 | 80.0 | 21.0 | 0 | 0 |

회복 계기 분석은 고객 감정이 크게 오르기 직전의 상담원 발화를 모아 표현 유형별 lift를 계산합니다. 첫 통화에서는 "다시 보내 드리도록 요청했고 쿠폰도 넣어 드렸습니다"가 계기로 잡혔습니다.

## 대시보드

배포 방법은 [대시보드 배포](docs/deploy.md)에 있습니다. 첫 방문 시 합성 샘플 데이터로 DB를 자동으로 만듭니다.

사이드바는 **홈(예시 결과) / 직접 분석 / 분석 기준** 세 화면입니다. 분석 기준의 **정확도** 탭에서 실제 데이터로 잰 정확도를 볼 수 있고, 직접 분석 결과에는 도메인별 신뢰도 안내가 붙습니다. 홈은 직접 분석을 하면 결과가 어떻게 나오는지 합성 데이터로 미리 보여주며, 아래 다섯 탭으로 나뉩니다. 모든 화면 맨 위에 "자동 추정치이며 진단·개인 평가 용도가 아니다"라는 고지가 고정되어 있습니다. 아래 화면은 합성 데이터로 만든 것입니다.

| 홈의 탭 · 사이드바 화면 | 내용 |
|---|---|
| 요약 | 채널별 추정 CSAT%·CES·NPS 성향, 우선 개선 과제, 조용한 불만, CSAT 모델 검증 요약 |
| 리뷰 | 브랜드·리뷰 이벤트 필터, 지수 6개(신뢰구간), 우선순위 × 난이도 4분면, 브랜드별 불만 비율, 여정 단계·속성별 감성, 별점–감정 불일치 |
| 상담 | 통화 목록(좌절·회복·CES), 고객·상담원 감성 시간축과 감정 급변 구간, 회복 계기(직전 상담원 발화), 전사본, 회복 직전 표현 lift |
| 영상 | 문장 감성 시간축 + 내용 구간 + 타임스탬프 댓글, 구간 요약, 크리에이터 vs 시청자 감성 |
| 채널 비교 | 도메인 선택, 채널별 CX 지표, 불만 유형 구성비 히트맵, 조용한 불만, CSAT 모델 검증 |
| **직접 분석** (사이드바) | 리뷰 CSV(열 자동 추정, UTF-8·CP949), 상담 전사본(텍스트 `화자: 발화` 붙여 넣기 / JSON, 같은 이름의 WAV면 음향 분석 추가), 영상 자막(VTT·SRT)+댓글 / 번들 JSON / YouTube 주소. 방문자 전용 메모리 DB에서 분석하고 저장하지 않음 |
| **분석 기준** (사이드바) | 감정 사전과 7감정 좌표, 지수 공식, 불만 분류표(소분류 31개, 도메인별 17~21개), CX 신호, 상담·영상 규칙, CX 추정 공식. 설정 파일에서 바로 만들어 실제 규칙과 항상 같음 |

## 채널 통합 CX 해석

`voclens cx`는 세 채널의 분석 결과를 모아 CX 지표를 추정하고 채널을 비교합니다. [샘플 CX 리포트](docs/sample_cx_report.md)에서 결과를 볼 수 있습니다.

| 지표 | 추정 방법 |
|---|---|
| **CSAT** | 리뷰 별점을 정답 대용으로 써서 릿지 회귀를 학습한 뒤 상담·영상에 적용합니다. 특징은 감정, 지수, CX 신호 13개입니다. 만족 비율(4점 이상)의 기준값은 학습 데이터의 실제 만족 비율에 맞춰 보정합니다 |
| **CES** | 좌절 지수 60%, 반복 문의 20%, 대기 10%, 미해결(보류·이관) 10%로 1(쉬움)~7(어려움) 점수를 만듭니다 |
| **NPS 성향** | 추천·재주문 의사는 추천 고객, 이탈·비추천 의사는 비추천 고객입니다. 표현이 없으면 "판단 불가"로 두고 판단 가능 비율을 함께 보여줍니다 |

채널 비교는 원점수가 아니라 **불만 유형 구성비**로 합니다. 리뷰는 긍정 쪽으로, 상담은 부정 쪽으로 치우쳐 있기 때문입니다.
- **조용한 불만:** 상담이나 영상 댓글에서는 비중이 큰데 리뷰에서는 작은 유형을 찾습니다. 리뷰만 보면 놓치는 불만입니다.
- **리뷰에서만 큰 불만:** 반대로 리뷰에서만 비중이 큰 유형입니다.
- **도메인 분리:** 같은 도메인(배달 / 제품)끼리만 비교합니다.
- **소표본 표시:** 불만 언급이 20건 미만인 채널은 "표본 적음"으로 표시합니다.

합성 리뷰로 검증한 CSAT 모델 결과입니다. 학습에 쓰지 않은 리뷰 38건으로 평가했고, 실제 데이터 성능이 아닙니다. 실제 쇼핑 리뷰로 옮기면 순서는 유지되지만 만족 비율이 크게 부풀어서, 대시보드의 CSAT 비율은 같은 데이터 안에서 비교하는 용도로만 읽어야 합니다 ([평가 7절](docs/evaluation.md#7-csat-추정-모델을-실제-리뷰로)).

| 모델 | 별점 예측 MAE |
|---|---|
| 상수 기준선 (평균 별점) | 1.236 |
| Valence 하나만 쓰는 회귀 | 0.697 |
| 전체 특징 릿지 회귀 | **0.564** (Spearman ρ 0.70) |

## 영상 분석 흐름

```
번들 JSON 또는 YouTube URL (사람이 단 자막만 사용, 없으면 --stt로 Whisper 전사 + pyannote 화자 분리, 댓글은 Data API)
    → 문장 분리 + 시각 보간, 구독·좋아요 같은 상투 문구 제거
    → 주 화자(크리에이터) 판정
    → 문장 감정, [WAV가 있거나 STT를 했으면] 음향 각성 융합과 말–톤 불일치 표시
    → 불만 유형·속성 (영상 도메인에 맞는 분류만: 제품 / 배달)
    → 내용 구간 분할 (TextTiling) → 도입·언박싱·사용·장단점·총평
    → 영상 유형 (리뷰·브이로그·인터뷰·상담 재연·뉴스)
    → 댓글 감정·불만 유형, "3:20" 타임스탬프 → 구간 연결
    → 크리에이터 지수, 총평 가중 Valence, 시청자 지수, 시청자 반응 기반 몰입 지수
```

합성 무선청소기 리뷰 영상의 구간 결과입니다. 실제 영상이 아닙니다.

| 구간 | 시간 | Valence | 주요 속성 | 타임스탬프 댓글 | 댓글 Valence |
|---|---|---|---|---|---|
| 도입 | 0:00~0:16 | 0.00 | — | 0 | — |
| 언박싱 | 0:20~1:06 | +0.20 | 포장, 배터리, 디자인 | 1 | +0.52 |
| 사용 | 1:06~1:42 | +0.19 | 성능, 사용성 | 2 | +0.40 |
| 사용 | 1:42~2:38 | -0.14 | 배터리, 성능 | 2 | -0.33 |
| 장단점 | 2:38~3:34 | -0.11 | 가격, 디자인, 사용성 | 1 | -0.30 |
| 총평 | 3:34~4:04 | +0.16 | 배터리 | 0 | — |

크리에이터가 배터리·소음을 말한 구간(1:42~)을 시청자도 타임스탬프 댓글로 짚었습니다. 이 구간에서는 시청자 감정도 함께 부정으로 바뀝니다.

## 리뷰 분석 흐름

```
CSV → 정제 (반복 문자, 이모티콘 → 감정 토큰, 개인정보 마스킹, 리뷰 이벤트 표시)
    → 절 분리 ("맛은 좋은데 / 배달이 늦어요")
    → 감정 (7감정 → Valence·Arousal)
    → 불만 유형·속성 (배달 도메인은 소분류 17개, 제품은 21개)
    → CX 신호 (재주문·이탈·추천 의사, 반복 문의, 대기, 해결)
    → 고객 여정 단계
    → 지수 6개 + Peak-End + 채널 내 백분위
    → SQLite → SQL 집계 / 개선 과제 리포트
```

배포 화면은 **사전·규칙 기반 기준선**으로 분류합니다. 학습한 감정 모델과 약지도 불만 분류기도 같은 인터페이스로 붙어 있어서, CLI에서 `--emotion-model`, `--complaint-model`로 바꿔 쓸 수 있습니다. 둘의 비교는 아래 실제 데이터 평가에 있습니다.

## 실제 데이터 평가

규칙 기반 기준선이 실제 데이터에서 어디까지 맞는지 공개 데이터로 쟀습니다. 규칙은 개발용 80%만 보고 고치고, 지표는 평가용 20%로 냈습니다. → [실제 데이터 평가](docs/evaluation.md)

| 평가 | 결과 |
|---|---|
| 네이버 쇼핑 평가용 39,807건: 1~2점 리뷰에 불만 유형이 붙은 비율 | 분류 기준 v0.2.1 15% → **v0.3.0 35%** (쇼핑 유형 10개 추가, 부정 처리) |
| 같은 데이터: 리뷰 감성으로 고득점·저득점을 가르는 AUC | 0.856 |
| KOTE 5천 문장: 감정 사전의 극성 정확도 | 판단한 문장에서 72.5%(긍정 91%, 부정 57%), 감정 표현 검출 44% → 부정 감정을 많이 놓친다 |
| 라벨링한 평가 세트 337개 절 (무작위, 규칙을 못 본 Claude 라벨러 2명, κ 0.96) | 불만 여부 F1 0.14 → **0.46** (정밀도 0.80, 재현율 0.32), 유형 micro F1 0.41 |
| **학습한 감정 모델** (KOTE 4만 문장, koelectra-small, CPU 67분) | KOTE 극성 AUC 0.71 → **0.98**, 부정 문장 정확도 57% → **99%**. 쇼핑 평가 세트 불만 여부 F1 0.46 → **0.54** (재현율 0.32 → 0.44, 정밀도 0.80 → 0.70) |
| **오탐 정리(규칙 v0.3.1) + 약지도 불만 분류기** | 규칙 v0.3.1: 정밀도 0.80 → **0.88**. 학습 감정 모델 + 규칙 ∪ 분류기: 불만 여부 F1 **0.59** (재현율 0.55, 정밀도 0.64), 사이즈·색상 재현율 0.15 → 0.54 |
| 손으로 정한 상수 19개를 0.5~1.5배로 흔들기 (하나씩, 그리고 동시에 500번) | 지수 순위 Spearman 최저 0.998 (참여 지수만 0.913), 개선 과제 순위 최저 0.994 (쇼핑) / 0.972 (합성 배달), 상담 CES 순서 그대로 |
| CSAT 모델을 쇼핑 리뷰 4만 건으로 다시 학습, 평가용 전체로 평가 | MAE 상수 1.585 → **1.055**, 만족 구분 AUC 0.858. 합성 배달로 학습한 배포 모델을 옮기면 MAE 1.228, 만족 비율 50% → **80.8%로 부풀림** |
| 음향 각성 규칙을 공개 감정 음성 RAVDESS 1,440개로 (가중치 그대로) | 각성 높음 vs 낮음 AUC **0.876** (화자 정규화 없으면 0.821), 배우 24명 중 최저 0.75. 에너지 하나만 써도 0.921이라 가중합이 더 낮음 |
| 같은 규칙을 CREMA-D 7,442개로 교차 확인 (배우 91명) | AUC **0.829** (정규화 없으면 0.813). 0.7 미만 배우 9명, 남성 0.773으로 여성 0.883보다 낮음. 쉼 비율 부호가 두 데이터 모두 반대 |
| 실제 YouTube 리뷰 영상 2편을 URL로 수집해 분석 (정답 라벨 없음, 동작 점검) | 수집 5~6초. 크리에이터 문장 82~89%가 감성 0, 내용 구간 분할은 도입이 네 번 나오는 등 쓸 수 없는 수준. 영상 밖 자막 큐, 문장 이어 붙이기, 도메인 누락을 고침 |
| 자막 없는 리뷰 영상 1편을 STT로 (Whisper medium, pyannote, CPU) | 5분 영상에 771초. STT 신뢰도 평균 0.893, 화자 1명, 71문장 모두 음향 각성이 붙음. 전사 정확도(CER)는 정답 전사본이 없어 못 잼. ffmpeg 없이 돌도록 고치고, 영상에서 음향 각성이 계산되지 않던 버그를 고침 |

규칙 기준선은 잡으면 대체로 맞지만(정밀도 0.88) 불만 3개 중 2개를 놓칩니다. 학습 모델을 쓰면 놓치는 불만이 크게 줄지만 오탐이 늘어서, 서비스 목적(모니터링 vs 보고)에 따라 고릅니다. 배포 화면은 정밀도가 높은 규칙 + 감정 사전이고, 학습 모델은 CLI의 `--emotion-model`, `--complaint-model`로 씁니다. 평가 세트 라벨은 사람이 아니라 Claude가 붙였습니다. 사람 검수 20절에서 불만 여부 κ는 0.78이었고, 유형은 덜 맞았습니다.

```
configs/            분류 기준, 감정·CX 신호 사전, 여정 단계, 기본 설정
src/voclens/
  text/             정제, 절 분리, 감정, 불만 유형, 여정 단계, CX 신호
  audio/            화자 역할 판정, 대화 역학, 음향 특징, 음성 각성, STT·화자 분리 어댑터
  video/            영상 유형, 내용 구간 분할, 타임스탬프 댓글
  fusion/           음향 + 텍스트 융합
  indices/          지수 계산, 상담 지수, 감정 급변 탐지
  cx/               통계, 개선 과제 리포트, 회복 계기 분석, CSAT·CES·NPS 추정, 채널 비교
  store/            SQLite 스키마, SQL 집계 쿼리
  dashboard/        대시보드용 데이터 조회와 차트 (Streamlit 없이 테스트 가능)
  ingest/           리뷰 CSV, 상담 전사본, 자막(VTT/SRT), YouTube
  pipelines/        채널별 파이프라인 (리뷰, 상담, 영상)
  templates/        리포트 템플릿
app/                Streamlit 대시보드
labeling/           라벨링 기준서, Label Studio 설정
scripts/            합성 데이터 생성기, 공개 데이터 내려받기, 케이스 4 집계, 상수 민감도, CSAT, 음성 각성(RAVDESS, CREMA-D) 실험, 실제 YouTube 영상 점검
docs/               PRD, 분석 설계서, 구현 계획, 데이터 신청 목록, 분류 기준
tests/              단위·통합 테스트
```

## 데이터와 윤리

- 저장소에는 합성 데이터만 있습니다. AI Hub 등 외부 데이터는 재배포할 수 없어서 넣지 않습니다. 신청 방법은 [데이터 신청 목록](docs/data_sources.md)에 있습니다.
- 공개 데이터(네이버 쇼핑 리뷰 Public Domain, KOTE MIT)도 원문은 넣지 않고 `scripts/fetch_public_data.py`로 내려받습니다. 감정 음성(RAVDESS CC BY-NC-SA 4.0, CREMA-D ODbL 1.0)은 받는 곳을 `scripts/ser_acted_speech.py` 머리말에 적어 두었습니다. 저장소에는 원문 없는 지표만 둡니다.
- 배달앱·쇼핑몰은 크롤링하지 않습니다. 리뷰는 정당하게 확보한 CSV나 공개 데이터셋만 씁니다.
- 원문은 개인정보(전화번호, 이메일, 긴 숫자)를 가린 뒤 저장합니다.
- 지수는 추정치입니다. 의료 진단, 채용 평가, 직원 감시, 개인 평가에 쓸 수 없습니다.

## 0. 설계 원칙

1. **세 채널, 하나의 스키마**: 영상·상담 음성·리뷰를 모두 같은 분석 단위 스키마(0.2)로 변환한다. 그래야 채널 간 비교가 된다.
2. **각성(Arousal)은 목소리로, 긍정·부정(Valence)은 말의 내용으로**:
   - 음성 감정 연구에서 일관되게 나오는 결과가 있다. 목소리는 "얼마나 흥분했는가"를 잘 드러내지만 "좋은가 나쁜가"는 잘 구분하지 못한다. 반대로 텍스트는 Valence를 잘 잡는다.
   - 그래서 융합 가중치를 차원마다 다르게 둔다 (5장).
3. **절대값보다 기준 대비 값**:
   - 사람마다 목소리 높이와 크기가 다르다. 음향 특징은 **화자 개인 기준으로 정규화**한다.
   - 채널마다 감정 분포도 다르다. 리뷰는 리뷰 이벤트 때문에 긍정 쪽으로, 상담은 문제가 있을 때 걸기 때문에 부정 쪽으로 치우친다. 그래서 지수는 **채널별 기준 코퍼스 대비 백분위**로도 함께 제공한다.
4. **평균만 보지 않는다 (Peak-End)**: 고객은 경험의 평균이 아니라 **가장 강렬했던 순간과 마지막 순간**을 기억한다 (Kahneman의 Peak-End Rule). 세션 단위 지수는 평균과 함께 최고점, 임계치 초과 시간, 종료 시점 값을 함께 낸다.
5. **모든 수치에 근거와 신뢰도**: 점수마다 근거 발화·문장과 신뢰도를 붙인다. 표본이 작으면 신뢰구간을 표시한다.

### 0.1 분석 단위
| 채널 | 최소 단위 | 상위 단위 |
|---|---|---|
| 리뷰 | 절(clause): "맛은 좋은데 / 배달이 늦어요" | 리뷰 → 매장·브랜드 → 기간 |
| 상담 음성 | 발화(turn): 화자 한 번의 말 | 통화 → 상담 유형 → 기간 |
| 영상 | 발화 → 내용 구간(segment) | 영상 → 채널·브랜드 |

### 0.2 공통 출력 스키마 (단위별)
```
unit_id, source_type(review|call|video), source_id, speaker_role(customer|agent|creator|commenter),
start_sec, end_sec,                     # 음성·영상만
text,
valence(-1~1), arousal(0~1),
emotion_probs{기쁨, 슬픔, 분노, 불안, 놀람, 혐오, 중립},
aspect, aspect_sentiment,               # 속성 (맛, 배달, 가격, 응대 ...)
complaint_category[], journey_stage,
cx_signals{repeat_contact, churn_intent, repurchase_intent, recommend_intent, resolution, empathy},
confidence{stt, audio, text, fusion}
```

## 1. 리뷰 텍스트 분석

### 1.1 파이프라인
```
CSV ─► ①정제·필터 ─► ②문장·절 분리 ─► ③감정 분류 ─► ④속성 기반 감성(ABSA)
    ─► ⑤불만 유형 분류 ─► ⑥CX 신호 탐지 ─► ⑦신규 이슈 발견 ─► ⑧집계·통계
```

### 1.2 단계별 방법
| 단계 | 방법 | 도구·모델 |
|---|---|---|
| ① 정제·필터 | 반복 문자 정규화("ㅋㅋㅋㅋㅋ" → "ㅋㅋ"), 띄어쓰기 교정, 이모지·이모티콘을 감정 토큰으로 변환("ㅠㅠ" → [슬픔]), 개인정보 마스킹, 중복·광고 제거. **리뷰 이벤트 참여 리뷰에는 표시**를 남긴다 ("리뷰이벤트", "서비스 감사" 등). 긍정 편향의 주요 원인이라 분석할 때 분리해서 본다 | soynlp, PyKoSpacing, 정규식 |
| ② 문장·절 분리 | 문장 분리 후 대조 접속 표현("~는데", "근데", "하지만", "~지만")에서 절을 나눈다. 한 리뷰 안의 상반된 평가를 분리하기 위해서다 | kss + 규칙 |
| ③ 감정 분류 | 온라인 댓글 감정 데이터로 학습된 다중 라벨 감정 모델로 절마다 감정 확률을 구한다. 그 결과를 7감정과 Valence·Arousal로 매핑한다 | KOTE 기반 모델 또는 KcELECTRA를 AI Hub 감성 대화 말뭉치로 파인튜닝 |
| ④ ABSA | 절마다 속성(맛, 양, 배달, 가격, 포장, 응대, 앱)과 그 속성에 대한 감성을 판정한다 | KLUE-RoBERTa를 AI Hub 속성기반 감정분석 데이터로 파인튜닝 (Colab) |
| ⑤ 불만 유형 분류 | 다중 라벨 분류. LLM 없이 **3단계 약지도 학습**으로 만든다 (1.3) | ko-sroberta / bge-m3 임베딩, KcELECTRA |
| ⑥ CX 신호 | 재주문 의사, 이탈 의사, 반복 문의, 추천 의사, 해결 여부, 회복 표현을 탐지한다. 처음에는 사전·패턴으로 시작하고 라벨이 쌓이면 분류기로 바꾼다 | 규칙 + 분류기 |
| ⑦ 신규 이슈 발견 | 기존 분류 기준에 안 맞는 불만을 토픽 모델링으로 찾아 **분류 기준 개정 후보**로 제안한다 | BERTopic + 한국어 임베딩 |
| ⑧ 집계·통계 | 매장·브랜드·기간별 지수와 불만 비율, 신뢰구간 (1.4) | pandas, scipy, statsmodels |

### 1.3 불만 유형 분류: LLM 없이 만드는 방법
1. **시드 사전 + 임베딩 유사도 (Zero-shot)**: 분류마다 대표 문장 10~20개를 정의한다. 절 임베딩과 가장 가까운 분류를 붙이고, 유사도가 낮으면 "분류 불가"로 둔다.
2. **능동 학습으로 라벨링**: 모델이 가장 헷갈려하는 절(확률이 낮거나 상위 두 분류가 비슷한 것) 400~500개를 우선 직접 라벨링한다. 라벨링 도구는 Label Studio(무료)를 쓴다.
3. **파인튜닝**: 라벨 데이터로 KcELECTRA 다중 라벨 분류기를 학습한다 (Colab).
4. **평가**: 1주일 뒤 같은 데이터 100개를 다시 라벨링해 **자기 일치도(Cohen's κ)** 를 잰다. 라벨 기준이 흔들리는지 확인하기 위해서다. 목표는 κ 0.7 이상이다.

이 과정 자체가 공고의 "VoC 분류 기준 수립" 역량을 보여주는 포트폴리오 소재가 된다.

### 1.4 집계와 통계
- **작은 표본 보정**: 리뷰가 적은 매장의 지수는 전체 평균 쪽으로 당겨 보정한다 (베이지안 축소). 리뷰 3개짜리 매장이 1위로 올라오는 문제를 막는다.
- **신뢰구간**: 부트스트랩 95% 신뢰구간을 낸다.
- **차이 검정**:
  - 브랜드 A vs B 불만 유형 비율: 카이제곱 검정
  - 지수 비교: Mann-Whitney U 검정
  - 효과 크기도 함께 표시한다
- **별점–감정 불일치**: 감정 점수로 별점을 예측하는 회귀를 만든다. 잔차가 큰 리뷰를 불일치로 표시한다.
  - 예: 별점 5점인데 "배달 1시간 걸림" (리뷰 이벤트 때문일 가능성)
  - 예: 별점 1점인데 내용은 칭찬 (잘못 누름)

## 2. 상담 음성 분석

### 2.1 파이프라인
```
오디오 ─► ①전처리 ─► ②화자 분리·역할 판정 ─► ③STT ─► ④음향 특징·음성 감정
      ─► ⑤텍스트 분석(1장 재사용) ─► ⑥대화 역학 ─► ⑦융합·궤적 ─► ⑧통화 단위 지표
```

### 2.2 단계별 방법
| 단계 | 방법 | 도구·모델 |
|---|---|---|
| ① 전처리 | 16kHz 모노 변환, 음량 정규화, 음성 구간 검출(VAD), 잡음 수준(SNR) 측정 (융합 신뢰도에 사용) | ffmpeg, Silero VAD |
| ② 화자 분리·역할 판정 | 2인 화자 분리 후 누가 상담원인지 판정한다. 판정 규칙: (a) 인사 스크립트("○○센터 ○○○입니다") 포함 여부, (b) 정형 표현 비율("확인해 드리겠습니다", "불편을 드려 죄송합니다"), (c) 첫 발화자. 신뢰도가 낮으면 사용자가 수동으로 바꿀 수 있게 한다 | pyannote.audio |
| ③ STT | 도메인 어휘(상품명, "환불", "배송 조회")를 초기 프롬프트로 넣는다. 단어 타임스탬프와 발화별 STT 신뢰도(평균 로그확률)를 함께 저장한다 | faster-whisper (CPU: medium int8 / Colab: large-v3) |
| ④ 음향 특징 | 발화마다 eGeMAPS 88개 특징(피치, 강도, 지터·시머, 말 속도, 휴지 비율 등)을 뽑는다. **각 화자의 통화 초반 30초를 기준으로 z-score 정규화**한다 (원래 목소리가 높은 사람이 화난 것처럼 보이는 문제 방지) | openSMILE |
| ④ 음성 감정 | 사전학습 음성 감정 모델의 임베딩 위에 **한국어 감정 음성 데이터로 가벼운 분류기**(로지스틱 회귀 / MLP)를 학습한다. 범주 감정과 Arousal·Valence를 출력한다 | emotion2vec+ 임베딩, AI Hub 감정 음성 / KEMDy (Colab) |
| ⑤ 텍스트 분석 | 1장 파이프라인을 고객 발화에 적용한다. 단, **직전 상담원 발화를 문맥으로 함께 넣는다** ("네" 한마디도 앞 질문에 따라 의미가 다르기 때문) | 1장 모델 재사용 |
| ⑥ 대화 역학 | 아래 2.3 지표 | 자체 구현 |
| ⑦ 융합·궤적 | 발화 단위 융합(5장) → 지수 시계열을 지수이동평균으로 평활화 → **변화점 탐지**로 감정 급변 이벤트를 찾는다 | ruptures |
| ⑧ 통화 단위 지표 | 2.4 | |

### 2.3 대화 역학 지표 (좌절·회복 지수의 핵심 재료)
| 지표 | 정의 | 의미 |
|---|---|---|
| 발화 점유율 | 고객 발화 시간 / 전체 | 고객이 계속 설명해야 하는 상황 |
| 끼어들기 횟수 | 상대 발화 중 시작한 발화 수 (화자별) | 고객 끼어들기 증가 = 조급함 |
| 침묵·대기 | 2초 이상 무음 구간 총합, 최장 대기 | 보류, 조회 대기 |
| 반복 발화 | 고객 발화끼리 의미 유사도가 높은 쌍의 수 | 같은 설명 반복 = 노력 증가 |
| 상담원 공감 표현 | "불편을 드려", "죄송합니다", "충분히 이해" 등 | 회복 계기 후보 |
| 해결 표현 | "처리됐습니다", "접수 완료", "환불 진행" vs "확인 후 연락", "다른 부서" | 해결 / 미해결 / 이관 |

### 2.4 통화 단위 산출물
- 6개 지수 (평균, 최고점, 임계치 초과 시간 비율, 종료 30초 값)
- **Peak-End 점수** = (최고 부정 강도 + 종료 시점 감정) / 2 → 고객이 기억할 경험의 추정치
- 통화 결과: 해결 / 미해결 / 이관
- **회복 계기 분석**: 고객 Valence가 크게 오른 시점 직전에 어떤 상담원 발화가 있었는지 모은다. 여러 통화를 모으면 "어떤 응대 표현 뒤에 고객 감정이 회복되는가"를 볼 수 있다 (사건 연구 방식). 상담 매뉴얼 개선으로 이어지는 **기획 인사이트**다.

## 3. 영상 분석

### 3.1 파이프라인
```
URL ─► ①메타데이터·오디오 수집 ─► ②배경음 분리 ─► ③자막/STT ─► ④화자 분리·주 화자
    ─► ⑤영상 유형 분류 ─► ⑥내용 구간 분할 ─► ⑦음성+텍스트 감정·ABSA ─► ⑧댓글 분석 ─► ⑨영상 단위 종합
```

### 3.2 단계별 방법
| 단계 | 방법 | 도구·모델 |
|---|---|---|
| ① 수집 | 오디오와 함께 메타데이터(제목, 채널, 업로드일, 조회수, 좋아요, 카테고리, 설명)를 저장한다 | yt-dlp, YouTube Data API v3 |
| ② 배경음 분리 | YouTube는 배경음악이 많다. 보컬 분리 후 음악만 있는 구간은 분석에서 뺀다 | Demucs (Colab), CPU에서는 생략 옵션 |
| ③ 자막/STT | **사람이 단 자막이 있으면 우선 사용**하고(정확도가 높음), 없으면 Whisper를 쓴다. 자동 생성 자막은 쓰지 않는다 | yt-dlp 자막, faster-whisper |
| ④ 화자 분리 | 발화 시간이 가장 긴 화자를 "주 화자(크리에이터)"로 둔다. 인터뷰형은 질문자와 응답자를 구분한다 | pyannote.audio |
| ⑤ 영상 유형 분류 | 리뷰·언박싱 / 브이로그 / 인터뷰 / 상담·응대 재연 / 기타로 분류한다 (메타데이터 + 자막 앞부분 임베딩). **유형마다 해석 기준이 다르다.** 예: 리뷰 유튜버는 평소에도 텐션이 높아 각성이 과대평가된다 → 화자 기준 정규화 + 유형별 기준 코퍼스 사용 | 임베딩 유사도 + 규칙 |
| ⑥ 내용 구간 분할 | 자막 문장 임베딩의 유사도가 급락하는 지점에서 구간을 나눈다 (TextTiling 방식). 예: 리뷰 영상 = 도입 / 언박싱 / 사용 / 장단점 / 총평. 각 구간에 속성과 고객 여정 단계를 붙인다 | 임베딩 + 변화점 탐지 |
| ⑦ 감정·ABSA | 2장 음성 감정 + 1장 텍스트 분석을 발화 단위로 적용하고 융합한다. **말과 톤의 불일치**도 표시한다 (말로는 "괜찮네요"인데 톤은 저활력·부정) | 1·2장 재사용 |
| ⑧ 댓글 분석 | 댓글을 리뷰 파이프라인으로 분석한다. 추가로 **"3:20" 같은 타임스탬프가 있는 댓글을 영상 타임라인에 연결**해, 시청자가 반응한 장면과 크리에이터의 감정을 겹쳐 본다 | YouTube Data API, 1장 재사용 |
| ⑨ 영상 단위 종합 | 6개 지수, 구간별 감정, **총평 구간 가중** (결론부 평가가 시청자 인식에 큰 영향), 크리에이터 감정 vs 시청자(댓글) 감정 비교 | |

## 5. 융합 방법

### 5.1 차원별 가중치 (초기값)
| 차원 | 음향 가중치 | 텍스트 가중치 | 근거 |
|---|---|---|---|
| Arousal (각성) | 0.7 | 0.3 | 목소리가 각성을 더 잘 드러냄 |
| Valence (긍정·부정) | 0.3 | 0.7 | 말의 내용이 긍정·부정을 더 잘 드러냄 |

### 5.2 학습된 융합
- KEMDy처럼 음성과 텍스트가 함께 있는 데이터로 **스태킹 분류기**(로지스틱 회귀)를 학습해 가중치를 데이터로 정한다.
- 초기값(5.1)과 학습값을 비교한 결과를 검증 리포트에 싣는다.

### 5.3 신뢰도 기반 동적 조정
- STT 신뢰도가 낮으면 (웅얼거림, 잡음) → 텍스트 가중치를 낮춘다.
- SNR이 낮거나 음악이 섞였으면 → 음향 가중치를 낮춘다.
- 발화가 1초 미만이면 → 음향 감정을 신뢰하지 않는다.

### 5.4 보정 (Calibration)
- 모델 확률이 실제 정답률과 맞도록 온도 스케일링으로 보정한다.
- 지수는 0~100 원점수와 함께 **채널별 기준 코퍼스 대비 백분위**를 제공한다. 예: "스트레스 70 = 상담 기준 코퍼스 상위 30%".

## 6. CX 해석 레이어 (P1 고도화 상세)

### 6.1 고객 여정 단계 태깅 (F-41)
- 도메인별 여정 단계를 정의한다.
  - 배달: 탐색 → 주문·결제 → 조리·대기 → 배달 → 수령·섭취 → 문의·환불 → 재주문
  - 일반 제품: 인지 → 구매 → 배송 → 개봉·설치 → 사용 → A/S → 재구매·추천
- 분류는 불만 유형과 같은 3단계 약지도 학습(1.3)으로 만든다.
- 히트맵 칸마다 **표본 수와 신뢰구간**을 함께 표시하고, 표본이 30개 미만이면 흐리게 표시한다.

### 6.2 CSAT / CES / NPS 추정 (F-42)
| 지표 | 추정 방법 | 한계 표시 |
|---|---|---|
| **CSAT** | 리뷰 별점을 CSAT의 대리 정답으로 쓴다. 리뷰 특징(감정, 속성 감성, CX 신호)으로 별점을 예측하는 모델을 학습하고, 같은 특징을 뽑을 수 있는 상담·영상에 적용한다 | 도메인 이동(리뷰 → 음성) 오차가 있음을 명시하고, 상담 데이터 일부로 따로 검증 |
| **CES** | 좌절 지수 + 반복 문의·대기·이관 신호를 1~7점 척도로 변환 | 공식 CES 설문과 다름을 명시 |
| **NPS 성향** | 추천·재구매 의사 → 추천 고객, 이탈 의사 → 비추천 고객, 나머지 → 중립 고객으로 나누고 비율 산출 | 표현이 명시적으로 드러난 경우만 분류, 나머지는 "판단 불가" |

### 6.3 채널 간 비교 (F-43)
- **원점수를 그대로 비교하지 않는다.** 리뷰는 긍정, 상담은 부정 쪽으로 치우쳐 있어 원점수 비교는 의미가 없다.
- 비교 방법:
  1. 채널 안에서 표준화한 지수(z-score, 백분위)
  2. **불만 유형 구성비** 비교 (예: 리뷰에서는 맛 불만이 많고, 상담에서는 배달 누락이 많음)
  3. 채널마다 다르게 보이는 이슈 탐지: 상담에서 많지만 리뷰에는 안 드러나는 이슈 = "조용한 불만" 후보
- 같은 이슈가 채널을 넘어 함께 늘어나는지 기간별로 교차 확인한다.

### 6.4 개선 과제 리포트 (F-44, LLM 없이)
1. **우선순위 점수** = 빈도(비율) × 감정 강도(스트레스·좌절 평균) × 추세(최근 기간 증가율) × 비즈니스 영향(재주문 의사 감소·이탈 의사와의 연관도)
2. **실행 난이도**: 불만 분류마다 미리 정의한 난이도 표 (예: 포장 개선 = 낮음, 배달 시간 단축 = 높음). 사용자가 조정할 수 있다.
3. **영향도×난이도 매트릭스**로 Quick Win / 핵심 과제 / 장기 과제 / 보류 4분면을 나눈다.
4. **근거 문장 자동 선택**: 이슈 클러스터의 중심에 가장 가까운 원문 3개 (대표성) + 감정 강도가 가장 높은 원문 1개 (심각성)
5. **문장 생성은 템플릿 기반**: "{기간} 동안 {브랜드}의 {불만 유형} 언급이 {증가율}% 늘었고, 해당 고객의 재주문 의사는 {차이}%p 낮았다."
6. (선택) Colab에서 오픈소스 LLM(Qwen2.5-7B-Instruct 등)으로 요약 문장만 다듬는다. 기본 기능은 LLM 없이도 완결된다.

### 6.5 기타 P1 고도화
| 기능 | 고도화 내용 |
|---|---|
| F-05 배치 분석 | 작업 큐 + 진행률 표시. 실패한 항목은 재시도하고 실패 사유를 기록 |

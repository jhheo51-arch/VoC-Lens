# 실제 데이터 평가

VoC Lens의 감정·불만 분류는 사전·규칙 기반 기준선입니다. 합성 데이터로는 "의도한 패턴을 찾는지"만 보여 줄 수 있어서, 공개된 실제 한국어 데이터로 **어디까지 맞고 어디서 놓치는지**를 쟀습니다.

## 데이터

| 데이터 | 규모 | 라벨 | 라이선스 | 용도 |
|---|---|---|---|---|
| [네이버 쇼핑 리뷰](https://github.com/bab2min/corpus) | 20만 건 (2020년 6~7월) | 별점 1·2·4·5 | Public Domain | 불만 유형 분류, 케이스 4 |
| [KOTE](https://github.com/searle-j/KOTE) | 댓글 5만 문장 (평가에는 test 5천 문장) | 44개 감정, 문장당 5명 | MIT | 감정 사전 |

- 원문은 저장소에 넣지 않습니다. `python scripts/fetch_public_data.py`로 `data/external/`에 내려받습니다 (`.gitignore` 대상). 저장소에는 원문 없는 지표 JSON(`experiments/results/`)만 둡니다.
- 네이버 쇼핑 리뷰 앞의 "재구매"는 고객이 쓴 말이 아니라 재구매 고객 표시입니다. 떼어서 `repeat_buyer` 열로 옮깁니다. 그대로 두면 재구매 의향 신호로 잘못 셉니다.

## 규칙을 고친 데이터와 평가한 데이터를 나눴다

규칙을 보고 고친 데이터로 정확도를 재면 점수가 부풀려집니다. 그래서 네이버 쇼핑 리뷰를 줄 번호 해시로 나눴습니다 (`voclens.evaluation.split_of`).

| 구분 | 비율 | 쓰임 |
|---|---|---|
| 개발용 | 80% (약 16만 건) | 놓친 리뷰를 읽고 분류 기준을 고친다 |
| 평가용 | 20% (39,807건) | 지표 계산, 라벨링 평가 세트, 케이스 4. 규칙을 고칠 때 보지 않는다 |

## 1. 불만 유형: 별점을 대리 정답으로

정답 라벨이 없어도 별점으로 방향은 확인할 수 있습니다. 1~2점 리뷰라면 불만이 있을 가능성이 높으니, 거기에 불만 유형이 붙지 않으면 놓친 것입니다.

**평가용 39,807건, 분류 기준 v0.2.1 → v0.3.0**

| 지표 | v0.2.1 | v0.3.0 |
|---|---|---|
| 불만 유형이 붙은 1점 리뷰 | 17.1% | **36.9%** |
| 불만 유형이 붙은 2점 리뷰 | 13.9% | **33.9%** |
| 불만 유형이 붙은 4점 리뷰 | 3.6% | 9.4% |
| 불만 유형이 붙은 5점 리뷰 | 1.9% | 5.1% |
| 리뷰 평균 Valence로 4~5점과 1~2점을 가르는 AUC | 0.845 | 0.856 |

- v0.2.1의 제품 도메인은 영상 리뷰용(불량·성능·배터리·사용 편의)이라 온라인 쇼핑 불만을 대부분 놓쳤습니다. 개발용 리뷰를 읽고 10개 유형을 추가했습니다 ([분류 기준 개정 이력](voc_taxonomy.md#개정-이력)).
- 4~5점 리뷰에 붙는 비율도 늘었습니다. "배송이 늦었지만 괜찮아요"처럼 고득점 리뷰에도 실제 불만이 있어서 전부 오탐은 아닙니다. 아래 3번 평가 세트에서 불만 여부 정밀도는 0.80입니다.
- 그래도 1~2점 리뷰의 약 65%는 유형이 붙지 않습니다. 그중 15.7%는 "별로예요", "실망입니다"처럼 부정적이지만 이유가 없는 리뷰(분류 불가)이고, 나머지는 사전에 없는 표현이라 놓친 것입니다. **규칙 기반의 한계이고, 파인튜닝 모델로 넘어가는 이유입니다.**

결과 파일: `experiments/results/shopping_test_ratings_v0.2.1.json`, `shopping_test_ratings_v0.3.0.json`

## 2. 감정 사전: KOTE

**KOTE test 5,000문장, 감정 사전 v0.1 (고치지 않은 상태)**

| 지표 | 값 |
|---|---|
| 감정 표현이 하나라도 걸린 문장 | 43.7% |
| 극성 AUC (긍정만 / 부정만 고른 문장 3,465개) | 0.71 |
| 극성을 판단한 비율 (\|Valence\| ≥ 0.05) | 39.4% |
| 판단했을 때 극성 정확도 | 72.5% (긍정 91.2%, **부정 56.5%**) |
| 감정 6종 macro F1 | 0.16 |

| 감정 | 정밀도 | 재현율 |
|---|---|---|
| 기쁨 | 0.77 | 0.42 |
| 슬픔 | 0.82 | 0.12 |
| 분노 | 0.92 | 0.06 |
| 불안 | 0.82 | 0.03 |
| 혐오 | 0.63 | 0.01 |
| 놀람 | 0.67 | 0.02 |

**읽는 법**
- 사전에 걸리면 대체로 맞지만(정밀도 0.6~0.9), 걸리는 경우가 적습니다(재현율 0.01~0.42). 특히 부정 감정은 표현이 다양해서 많이 놓치고, 부정 문장의 극성 정확도가 56.5%에 그칩니다.
- KOTE는 뉴스·커뮤니티 댓글이 많아서 리뷰와 표현이 다릅니다. 리뷰 데이터(위 1번)에서는 AUC가 0.856으로 더 높습니다.
- KOTE 라벨은 5명 중 **1명 이상**이 고른 감정의 합집합입니다(문장당 평균 7.9개). 그래서 감정별 정밀도는 후하게, 재현율은 박하게 나옵니다. 극성 평가는 아무도 반대 극성 감정을 고르지 않은 문장만 써서 이 영향을 줄였습니다.
- KOTE train 4만 문장은 2단계 파인튜닝에 그대로 쓸 수 있습니다. 같은 test 5천 문장으로 기준선과 비교합니다.

KOTE 44감정은 VoC Lens 7감정으로 묶어 비교합니다 (`voclens.evaluation.KOTE_TO_EMOTION`). 깨달음·비장함처럼 대응이 애매한 감정은 감정별 평가에서 뺍니다.

결과 파일: `experiments/results/kote_test_lexicon.json`

## 3. 불만 유형: 라벨링한 평가 세트

별점은 "불만이 있을 것 같다"는 대리 지표일 뿐이라, 유형이 맞는지는 절마다 붙인 정답으로 재야 합니다.

**평가 세트**
- 평가용 리뷰를 별점마다 50건씩 무작위로 뽑고, 리뷰마다 절을 최대 2개 골라 **337개 절**을 만들었습니다.
- 라벨링 후보 추출(`voclens label prepare`)은 모델이 헷갈리는 절부터 고르지만, 평가 세트는 **무작위**입니다. 그래야 정확도가 편향되지 않습니다.

**라벨은 누가 붙였나 (중요)**
- 정답 라벨은 **Claude 에이전트 두 개가 따로** 붙였습니다(라벨러 A·B). 사람 라벨이 아닙니다.
- 두 라벨러는 분류 규칙(정규식)과 모델 예측을 보지 못하게 했습니다. 본 것은 [라벨링 기준서](../labeling/guidelines.md)와 정규식 없는 [유형 정의](../labeling/label_definitions_product.md)뿐입니다. 규칙을 만든 쪽이 정답까지 붙이면 점수가 부풀기 때문입니다.
- 두 라벨러의 일치도는 macro κ 0.96, "불만이 있나" 이진 κ 0.99입니다. 다만 **같은 모델을 두 번 돌린 것이라 사람 둘보다 높게 나옵니다.** 라벨이 일관적이라는 뜻이지, 정답이 맞다는 보장은 아닙니다.
- 확신이 없는 절은 보류로 표시했습니다(A 53개, B 49개). 아래 표는 보류를 뺀 값입니다.
- 사람이 일부(예: 50개)를 다시 라벨링해 Claude 라벨과의 일치도를 재는 것이 다음 검증 단계입니다.
- 라벨(절 ID와 유형만, 원문 없음): `labeling/eval/naver_shopping_eval_labels_A.json`, `_B.json`

**결과 (라벨러 A 기준, 보류 제외 284개 절 중 불만 절 88개)**

| 지표 | v0.2.1 | v0.3.0 |
|---|---|---|
| 불만 여부 정밀도 | 0.58 | **0.80** |
| 불만 여부 재현율 | 0.08 | **0.32** |
| 불만 여부 F1 | 0.14 | **0.46** |
| 불만 유형 micro F1 | 0.13 | **0.41** |
| 불만 유형 macro F1 | 0.12 | **0.37** |

라벨러 B를 정답으로 써도 v0.3.0은 불만 여부 F1 0.47, micro F1 0.40으로 거의 같습니다. 보류까지 넣으면(337개) 불만 여부 정밀도 0.84, 재현율 0.29입니다.

**유형별 (v0.3.0, 라벨러 A)**

| 유형 | 정답 절 | 정밀도 | 재현율 | F1 |
|---|---|---|---|---|
| 품질·마감 | 16 | 0.80 | 0.25 | 0.38 |
| 사이즈·색상 | 13 | 0.40 | 0.15 | 0.22 |
| 맛·신선도 | 11 | 1.00 | 0.55 | 0.71 |
| 배송 지연 | 7 | 0.60 | 0.43 | 0.50 |
| 성능 | 7 | — | 0.00 | 0.00 |
| 사용 편의 | 6 | 0.50 | 0.17 | 0.25 |
| 정보 불일치 | 6 | 1.00 | 0.33 | 0.50 |
| 가격 | 5 | 0.50 | 0.20 | 0.29 |
| 포장·파손 | 5 | 0.67 | 0.40 | 0.50 |
| 오배송·누락 | 4 | — | 0.00 | 0.00 |
| 효과 없음 | 4 | — | 0.00 | 0.00 |

정답 절이 3개 이하인 유형(문의·연락, 품질 편차, 제품 불량, 냄새, 환불·취소)은 표에서 뺐습니다. 표본이 작아 유형별 수치는 ±0.2 이상 흔들릴 수 있습니다.

**읽는 법**
- v0.3.0은 **잡으면 10개 중 8개는 불만이 맞지만, 불만 절 3개 중 2개는 놓칩니다.** 리뷰 단위 대리 지표(1~2점 리뷰의 35%에 유형이 붙음)와 같은 방향입니다.
- 오탐의 주된 원인
  - 단어만 보고 판단: "반품하기 귀찮아 그냥 썼다"의 '반품'을 제품 불량으로 봄
  - 주제 표현의 과대 적용: 연락 불만 문장의 '배송'을 배송 지연으로 봄
  - 앞에 오는 부정을 놓침: "부서진 것도 없어요"를 포장·파손으로 봄
  - 비슷한 유형 혼동: '비린내'를 냄새가 아니라 맛·신선도로 봄
- 놓침은 품질·마감, 사이즈·색상처럼 **표현이 다양한 유형**에 몰립니다. 규칙을 더 늘리기보다 학습 모델이 필요한 부분입니다.
- 이 오류들을 보고 규칙을 고치지 않았습니다. 평가 세트를 보고 규칙을 고치면 이 점수를 더는 믿을 수 없게 됩니다. 고칠 때는 개발용 데이터에서 같은 유형의 오류를 찾아 고치고, 평가 세트로 다시 잽니다.

결과 파일: `experiments/results/shopping_gold_v0.2.1.json`, `shopping_gold_v0.3.0.json`, `shopping_gold_v0.3.0_labeler_B.json`

```bash
voclens eval gold labeling/eval/naver_shopping_eval_labels_A.json --out experiments/results/shopping_gold_v0.3.0.json
git show 3516934:configs/taxonomy.yaml > taxonomy_v0.2.1.yaml
voclens eval gold labeling/eval/naver_shopping_eval_labels_A.json --taxonomy taxonomy_v0.2.1.yaml
```

## 4. 학습한 감정 모델 (2단계, 실험)

감정 사전은 걸리면 맞지만 놓치는 문장이 많았습니다. 그래서 KOTE train 4만 문장으로 한국어 감정 모델을 파인튜닝하고, 같은 평가 데이터로 비교했습니다.

| 항목 | 내용 |
|---|---|
| 모델 | `monologg/koelectra-small-v3-discriminator` (1,400만 파라미터, CPU 학습) |
| 학습 | KOTE train 40,000문장, 44감정 → 6감정 다중 라벨, 2 epoch, 최대 64토큰, CPU 67분 |
| 검증 | KOTE val 5,000문장 macro F1 0.72 (`experiments/results/emotion_kote_small_training.json`) |
| 평가 | KOTE test와 쇼핑 평가 세트는 학습에 쓰지 않음 |
| 출력 | 6감정 확률 → 중립 = Π(1 − p) → 7감정 정규화 → Valence·Arousal. 분류 기준의 Valence 임계치를 그대로 쓴다 |

**감정 극성 (KOTE test 3,465문장)**

| 지표 | 감정 사전 | 학습 모델 |
|---|---|---|
| 극성 AUC | 0.71 | **0.98** |
| 극성을 판단한 비율 | 39% | **97%** |
| 판단했을 때 정확도 | 72.5% | **94.1%** |
| 부정 문장 정확도 | 56.5% | **98.6%** |
| 긍정 문장 정확도 | **91.2%** | 84.9% |
| 전체 문장 기준 정확도 (판단 안 함 = 오답) | 28.5% | **90.8%** |

감정별 macro F1(대표 감정 하나가 맞는지)은 0.16 → 0.33입니다. 혐오·불안·놀람은 분노·슬픔과 함께 나오는 경우가 많아 대표 감정으로 거의 뽑히지 않습니다. KOTE 라벨이 합집합이라 감정마다 문장 절반 가까이가 양성이어서, 모델은 "부정이냐 긍정이냐"는 잘 배우지만 세부 감정 구분은 약합니다.

**쇼핑 리뷰에 적용 (분류 규칙 v0.3.0 그대로, 감성 점수만 교체)**

| 지표 | 감정 사전 | 학습 모델 |
|---|---|---|
| 평가 세트: 불만 여부 정밀도 | **0.80** | 0.70 |
| 평가 세트: 불만 여부 재현율 | 0.32 | **0.44** |
| 평가 세트: 불만 여부 F1 | 0.46 | **0.54** |
| 평가 세트: 불만 유형 micro F1 | 0.41 | **0.48** |
| 평가용 39,807건: 고득점·저득점 구분 AUC | 0.856 | **0.944** |
| 평가용: 1점 리뷰에 불만 유형이 붙은 비율 | 37% | **54%** |
| 평가용: 5점 리뷰에 불만 유형이 붙은 비율 | **5%** | 11% |

라벨러 B를 정답으로 써도 불만 여부 F1 0.54, micro F1 0.46으로 같은 결론입니다.

**정밀도를 지키려는 임계치 조정 (실패, 기록용)**

학습 모델로 재현율은 올랐지만 정밀도가 내려가서, "주제 표현 + 부정 감성" 규칙의 Valence 기준(`topic_max_valence`, 감정 사전은 0)을 조정해 정밀도를 되찾으려 했습니다. 평가 세트는 쓰지 않고 개발용 데이터에서만 골랐습니다.

| 방법 | 개발용에서 고른 값 | 평가 세트 불만 여부 (정밀도 / 재현율 / F1) |
|---|---|---|
| 조정 없음 | 0 | 0.70 / 0.44 / **0.54** |
| ① 별점 대리 지표: 5점 리뷰 불만 비율을 감정 사전 수준(5.1%)으로 묶고 1·2점 리뷰 불만 비율 최대 | −0.45 | 0.74 / 0.32 / 0.44 |
| ② 개발용 절 정답 329개(Claude 라벨러, 평가 세트와 겹치지 않음)에서 F1 최대 | +0.20 | 0.68 / 0.45 / **0.54** |

- ①은 실패했습니다. 기준을 엄격하게 하자 5점 리뷰의 오탐은 거의 줄지 않고, 1·2점 리뷰의 실제 불만을 놓쳤습니다. **"5점 리뷰의 불만 = 오탐"이라는 가정이 틀렸습니다.** 5점 리뷰에도 실제 불만 문장이 있고("배송은 늦었지만 만족"), 리뷰 단위 비율과 문장 단위 정확도는 다르게 움직입니다.
- ②의 개발용 F1은 +0.15~−0.05 구간에서 0.62로 평평했고, +0.20이 1문장 차이로 가장 높았습니다. 평가 세트에서도 조정 없음과 차이가 없었습니다.
- 결론: 이 기준값은 개선 수단이 아닙니다. 설정은 가장 단순한 0으로 둡니다. 정밀도를 지키려면 기준값보다 **불만 유형 분류 자체를 학습**하거나, 오탐이 많은 규칙(예: '반품' 단어, '배송' 주제 표현)을 개발용 데이터에서 고쳐야 합니다.
- 개발용 정답: `labeling/dev/naver_shopping_dev_labels.json` (원문 없음). 결과: `experiments/results/topic_threshold_tuning_rating_proxy.json`, `topic_threshold_tuning_dev_gold.json`, `shopping_gold_v0.3.0_koelectra_small_tuned.json`

**읽는 법**
- 감성 점수가 정확해지자, "주제 표현 + 부정 감성"으로 잡는 불만(예: "배송이 좀…")이 늘어서 재현율이 올랐습니다. 대신 부정 감성을 더 자주 내서 정밀도는 내려갔습니다.
- 서비스에서 무엇을 우선하느냐에 따라 선택이 갈립니다. **놓치지 않는 것**(위험 신호 모니터링)이 중요하면 학습 모델, **잡은 것을 믿는 것**(경영 보고용 수치)이 중요하면 감정 사전이 맞습니다.
- 배포된 대시보드는 아직 감정 사전을 씁니다. 학습 모델은 torch가 필요해서 무료 배포 환경에 올리기 무겁고, 정밀도 하락을 어떻게 다룰지 정한 뒤 바꿉니다. CLI에서는 `--emotion-model`로 쓸 수 있습니다.
- 다음 단계: 불만 유형 분류기 학습(개발용 절 정답 329개 + 규칙 약지도), 오탐이 많은 규칙 정리, 더 큰 모델(KcELECTRA-base, [Colab 노트북](../notebooks/train_emotion_colab.ipynb)).

## 5. 불만 유형 분류기 (2단계, 약지도) 와 규칙 v0.3.1

## 6. 손으로 정한 상수의 민감도

지수 식의 가중치(좌절 지수의 반복 문의 0.40 등), 우선순위 식의 0.5, CES 가중치는 데이터로 학습한 값이 아니라 손으로 정한 값입니다. 이 값이 결론을 좌우하는지 보려고 상수를 흔들어 봤습니다 (`scripts/sensitivity_constants.py`).

- 흔드는 방법: 상수 19개를 하나씩 ×0.5와 ×1.5로 바꾸고, 그다음 전부 동시에 ×U(0.5, 1.5)로 무작위로 바꾸기를 500번 했습니다 (seed 42).
- 기본값에서는 다시 구현한 식이 배포 코드(`unit_scores`, `engagement_index`, `pain_points`, `estimate_ces`)와 같은 값을 내는지 먼저 확인했습니다.

| 실험 | 대상 | 결과 (흔든 모든 경우 중 최악) |
|---|---|---|
| A. 지수 순위 | 쇼핑 평가용 리뷰 39,807건 (단위 89,678개) | 기본값 대비 순위 Spearman: 행복 0.998, 스트레스 1.000, 부정 정서 0.9999, 좌절 0.998, 참여 0.913 |
| A. 별점 구분력 | 같은 데이터, 별점 4·5 vs 1·2 AUC | 행복 0.80 → 최저 0.799, 좌절 0.710 → 0.709. 상수를 바꿔도 구분력이 거의 그대로 |
| B. 개선 과제 우선순위 | 쇼핑 유형 18개 (리뷰 40건 이상) | 순위 Spearman 최저 0.994, 1위 그대로 100%, 상위 3개 그대로 94.4%, 4분면 바뀐 비율 0 |
| B. 개선 과제 우선순위 | 합성 배달 유형 12개 | 순위 Spearman 최저 0.972, 상위 3개 그대로 100%, 1위 그대로 91.2%, 4분면 바뀐 비율 평균 5.7% |
| C. CES 순서 | 합성 상담 4건 | Kendall τ 최저 1.0, 가장 힘든 통화와 전체 순서 그대로 100% |

**읽는 법**
- 상수를 절반이나 1.5배로 바꿔도 순위와 과제 선정은 거의 그대로입니다. 결론을 정하는 것은 상수가 아니라 감정 점수와 불만 비중 자체입니다. 거꾸로 말하면 상수를 조정해서 결과를 좋게 만들 여지도 작습니다.
- 가장 흔들리는 것은 참여 지수(최저 0.913)입니다. 글자 수, 측면 수, 의도 세 가지 비중에 따라 순위가 조금 바뀝니다.
- 참여 지수의 별점 AUC는 0.44로 0.5보다 낮습니다. 불만 리뷰 쪽 참여 지수가 오히려 높다는 뜻입니다. 참여 지수는 "얼마나 공들여 말했나"이지 만족도가 아니라서 설계대로이지만, 만족 지표로 읽으면 안 됩니다.
- 상담 실험은 합성 4건이라 순서가 안 바뀐다는 것 이상을 말해 주지 못합니다.

결과 파일: `experiments/results/sensitivity_constants.json`

## 7. CSAT 추정 모델을 실제 리뷰로

배포 화면의 CSAT 추정 모델은 합성 배달 리뷰 155건으로 학습합니다. 실제 리뷰에서도 쓸 만한지 보려고 네이버 쇼핑 리뷰로 다시 학습하고 평가했습니다 (`scripts/csat_shopping.py`). 특징 13개는 배포 코드와 같은 `session_features`로 뽑았습니다.

- 학습: 개발용에서 무작위로 뽑은 리뷰 40,000건
- 평가: 평가용 전체 39,807건 (별점 1점 7,102, 2점 12,786, 4점 3,723, 5점 16,196. 실제 만족 비율 50.0%)

| 모델 | MAE | Spearman | 만족 구분 AUC | 추정 만족 비율 (실제 50.0%) |
|---|---|---|---|---|
| 상수 (학습 평균) | 1.585 | — | — | — |
| Valence 하나만 쓴 회귀 | 1.109 | 0.594 | 0.854 | 42.3% |
| **쇼핑으로 학습한 릿지 (특징 13개)** | **1.055** | **0.602** | **0.858** | 42.8% |
| 합성 배달로 학습한 릿지 (배포 화면과 같은 모델) | 1.228 | 0.559 | 0.836 | **80.8%** |

**읽는 법**
- 실제 리뷰로 학습하면 상수보다 MAE가 33% 줄고, 만족·불만을 AUC 0.86으로 가릅니다. 다만 Valence 하나만 써도 거의 같습니다(AUC 0.854). 나머지 특징 12개가 더하는 것은 작습니다.
- 합성 배달로 학습한 모델을 실제 쇼핑 리뷰에 옮기면 순서는 꽤 유지되지만(AUC 0.836), 합성 평가용에서 0.564이던 MAE가 1.228로 두 배 넘게 나빠지고 **만족 비율을 80.8%로 크게 부풀립니다.** 임계값을 합성 데이터에서 맞췄기 때문입니다. 배포 화면의 CSAT 비율은 절댓값이 아니라 같은 데이터 안에서 비교하는 용도로만 읽어야 합니다. 상담·영상처럼 별점이 없는 채널에 옮겨 쓸 때도 같은 문제가 생길 것으로 봅니다.
- 쇼핑으로 학습해도 추정 만족 비율은 42.8%로 실제보다 7%p 낮습니다. 감정 사전이 감정 신호를 하나도 못 잡는 리뷰가 약 31%라서, 이 리뷰들은 예측이 모두 같은 값입니다. 한 덩어리라 임계값으로 나눌 수 없습니다. 감정 사전의 재현율이 CSAT 추정의 한계를 정합니다.
- 계수는 해석하지 않습니다. Valence 관련 특징(평균, 최저, peak-end, 행복)끼리 겹쳐서, 좌절 지수 계수가 양수로 나오는 등 부호가 직관과 다릅니다.

**이 실험에서 찾은 버그.** 만족 임계값을 예측값의 분위수로 정했는데, 예측이 같은 값에 몰리면 분위수가 그 동점 값에 걸리고 `>=` 때문에 동점 전체가 만족으로 들어갔습니다. 고치기 전에는 학습 데이터에서도 실제 49.2%를 75%로 추정했습니다. 후보 임계값마다 만족 비율을 세서 실제 비율에 가장 가까운 값을 고르도록 고쳤고(`RidgeRegressor.calibrate_threshold`), 회귀 테스트를 넣었습니다. 합성 배달 데이터는 동점이 3% 미만이라 배포 화면의 임계값(3.620)과 수치는 바뀌지 않습니다.

결과 파일: `experiments/results/csat_shopping.json`

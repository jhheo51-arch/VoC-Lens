# 실제 데이터 평가

VoC Lens의 감정·불만 분류는 사전·규칙 기반 기준선입니다. 합성 데이터로는 "의도한 패턴을 찾는지"만 보여 줄 수 있어서, 공개된 실제 한국어 데이터로 **어디까지 맞고 어디서 놓치는지**를 쟀습니다.

절마다 **문제 정의 → 문제 해결(어떻게 실행했나, 어떤 노력을 했나) → 결과 검토(결과, 한계, 앞으로 추진)** 순서로 적었습니다. 한계는 "이 결과로 어디까지 말할 수 있는지"로 적었습니다.

## 데이터

| 데이터 | 규모 | 라벨 | 라이선스 | 용도 |
|---|---|---|---|---|
| [네이버 쇼핑 리뷰](https://github.com/bab2min/corpus) | 20만 건 (2020년 6~7월) | 별점 1·2·4·5 | Public Domain | 불만 유형 분류, 케이스 4 |
| [KOTE](https://github.com/searle-j/KOTE) | 댓글 5만 문장 (평가에는 test 5천 문장) | 44개 감정, 문장당 5명 | MIT | 감정 사전 |

- 원문은 저장소에 넣지 않습니다. `python scripts/fetch_public_data.py`로 `data/external/`에 내려받습니다 (`.gitignore` 대상). 저장소에는 원문 없는 지표 JSON(`experiments/results/`)만 둡니다.
- 네이버 쇼핑 리뷰 앞의 "재구매"는 고객이 쓴 말이 아니라 재구매 고객 표시입니다. 떼어서 `repeat_buyer` 열로 옮깁니다. 그대로 두면 재구매 의향 신호로 잘못 셉니다.

## 규칙을 고친 데이터와 평가한 데이터를 나눴다

규칙을 보고 고친 데이터로 정확도를 재면 점수가 부풀려집니다. 그래서 네이버 쇼핑 리뷰를 줄 번호 해시로 나눴습니다 (`voclens.evaluation.split_of`).

| 구분 | 비율 | 쓰임 |
|---|---|---|
| 개발용 | 80% (약 16만 건) | 놓친 리뷰를 읽고 분류 기준을 고친다 |
| 평가용 | 20% (39,807건) | 지표 계산, 라벨링 평가 세트, 케이스 4. 규칙을 고칠 때 보지 않는다 |

## 1. 불만 유형: 별점을 대리 정답으로

### 문제 정의

- 불만 유형 분류는 사전과 규칙으로 만든 기준선입니다. 실제 쇼핑 리뷰에서 불만을 얼마나 잡는지 알아야 했지만, 처음에는 절마다 붙은 정답 라벨이 없었습니다.
- 그래서 먼저 별점을 대리 정답으로 썼습니다. 1~2점 리뷰라면 불만이 있을 가능성이 높으니, 거기에 불만 유형이 붙지 않으면 놓친 것입니다.

### 문제 해결

**어떻게 실행했나.** 평가용 39,807건에 분류 기준을 돌려 별점마다 불만 유형이 붙은 비율과, 리뷰 평균 Valence로 고득점과 저득점을 가르는 AUC를 쟀습니다.

**어떤 노력을 했나.** 처음 버전(v0.2.1)은 제품 도메인이 영상 리뷰용(불량·성능·배터리·사용 편의)이라 온라인 쇼핑 불만을 대부분 놓쳤습니다. 평가용은 보지 않고 **개발용 리뷰만 읽어** 10개 유형을 추가해 v0.3.0을 만들었습니다 ([분류 기준 개정 이력](voc_taxonomy.md#개정-이력)).

### 결과 검토

**평가용 39,807건, 분류 기준 v0.2.1 → v0.3.0**

| 지표 | v0.2.1 | v0.3.0 |
|---|---|---|
| 불만 유형이 붙은 1점 리뷰 | 17.1% | **36.9%** |
| 불만 유형이 붙은 2점 리뷰 | 13.9% | **33.9%** |
| 불만 유형이 붙은 4점 리뷰 | 3.6% | 9.4% |
| 불만 유형이 붙은 5점 리뷰 | 1.9% | 5.1% |
| 리뷰 평균 Valence로 4~5점과 1~2점을 가르는 AUC | 0.845 | 0.856 |

**결과**
- 1~2점 리뷰에 불만 유형이 붙는 비율이 두 배 넘게 늘었습니다(17.1% → 36.9%).
- 4~5점 리뷰에 붙는 비율도 늘었습니다. "배송이 늦었지만 괜찮아요"처럼 고득점 리뷰에도 실제 불만이 있어서 전부 오탐은 아닙니다. 아래 3절 평가 세트에서 불만 여부 정밀도는 0.80입니다.

**한계: 이 결과로 말할 수 있는 범위는 아래로 제한됩니다**
- 별점은 리뷰 단위의 대리 지표라서, 붙은 유형이 맞는지는 이 결과로 말할 수 없습니다. 유형 정확도는 3절에서 잽니다.
- 1~2점 리뷰의 약 65%는 여전히 유형이 붙지 않습니다. 그중 15.7%는 "별로예요", "실망입니다"처럼 부정적이지만 이유가 없는 리뷰(분류 불가)이고, 나머지는 사전에 없는 표현이라 놓친 것입니다. 규칙만으로 재현율을 올리는 데는 한계가 있습니다.

**앞으로 추진**
- 놓친 표현은 규칙을 더 늘리지 않고 학습 모델로 잡습니다. 감정 모델 학습(4절)과 불만 분류기 학습(5절)으로 이어졌습니다.
- 이유 없는 부정 리뷰는 "분류 불가"로 따로 세어, 불만 유형 비중을 계산할 때 놓친 것과 섞이지 않게 합니다.

결과 파일: `experiments/results/shopping_test_ratings_v0.2.1.json`, `shopping_test_ratings_v0.3.0.json`

## 2. 감정 사전: KOTE

### 문제 정의

- 모든 지수는 감정 사전에서 나온 Valence와 감정 점수를 바탕으로 합니다. 감정 사전이 틀리면 지수 전체가 흔들리지만, 사전을 사람 라벨과 비교한 적이 없었습니다.
- 질문: **감정 사전은 사람이 단 감정 라벨과 얼마나 맞고, 어디서 놓치는가?**

### 문제 해결

**어떻게 실행했나.** 문장마다 5명이 44개 감정을 붙인 공개 데이터 KOTE의 test 5,000문장에 감정 사전 v0.1을 고치지 않은 상태로 돌렸습니다. KOTE 44감정은 VoC Lens 7감정으로 묶어 비교했습니다 (`voclens.evaluation.KOTE_TO_EMOTION`).

**어떤 노력을 했나.**
- 깨달음·비장함처럼 대응이 애매한 감정은 감정별 평가에서 뺐습니다.
- KOTE 라벨은 5명 중 **1명 이상**이 고른 감정의 합집합입니다(문장당 평균 7.9개). 그래서 극성 평가는 아무도 반대 극성 감정을 고르지 않은 문장(3,465개)만 써서, 합집합 라벨 때문에 점수가 왜곡되는 것을 줄였습니다.
- 사전이 판단을 아예 안 한 문장과 틀린 문장을 나눠 세서, 정확도 문제인지 재현율 문제인지 구분했습니다.

### 결과 검토

**KOTE test 5,000문장, 감정 사전 v0.1 (고치지 않은 상태)**

| 지표 | 값 |
|---|---|
| 감정 표현이 하나라도 걸린 문장 | 43.7% |
| 극성 AUC (긍정만 / 부정만 고른 문장 3,465개) | 0.71 |
| 극성을 판단한 비율 (\|Valence\| ≥ 0.05) | 39.4% |
| 판단했을 때 극성 정확도 | 72.5% (긍정 91.2%, **부정 56.5%**) |
| 감정 6종 macro F1 | 0.16 |

| 감정 | 정밀도 | 재현율 |
|---|---|---|
| 기쁨 | 0.77 | 0.42 |
| 슬픔 | 0.82 | 0.12 |
| 분노 | 0.92 | 0.06 |
| 불안 | 0.82 | 0.03 |
| 혐오 | 0.63 | 0.01 |
| 놀람 | 0.67 | 0.02 |

**결과**
- 사전에 걸리면 대체로 맞지만(정밀도 0.6~0.9), 걸리는 경우가 적습니다(재현율 0.01~0.42). 문제는 정확도보다 재현율입니다.
- 특히 부정 감정은 표현이 다양해서 많이 놓치고, 부정 문장의 극성 정확도가 56.5%에 그칩니다.
- 리뷰 데이터(1절)에서는 AUC가 0.856으로 더 높습니다. KOTE는 뉴스·커뮤니티 댓글이 많아서 리뷰와 표현이 다르기 때문입니다.

**한계: 이 결과로 말할 수 있는 범위는 아래로 제한됩니다**
- 합집합 라벨 때문에 감정별 정밀도는 후하게, 재현율은 박하게 나옵니다. 감정별 수치는 방향을 보는 용도로 제한됩니다.
- 감정 사전으로 계산한 세부 감정(분노, 불안, 혐오 등)은 재현율이 0.01~0.12라, 세부 감정 비중을 보고하는 데 쓰는 것은 제한됩니다.

**앞으로 추진**
- KOTE train 4만 문장으로 감정 모델을 파인튜닝하고, 같은 test 5천 문장으로 사전과 비교합니다. 이것이 4절입니다.
- 배포 화면은 가볍고 정밀도가 높은 감정 사전을 유지하고, 사전 보강은 평가용이 아닌 개발용 리뷰에서만 합니다.

결과 파일: `experiments/results/kote_test_lexicon.json`

## 3. 불만 유형: 라벨링한 평가 세트

### 문제 정의

- 별점은 "불만이 있을 것 같다"는 대리 지표일 뿐이라, 붙은 유형이 맞는지는 절마다 붙인 정답으로 재야 합니다.
- 정답을 붙일 사람 라벨러를 바로 구할 수 없었고, 규칙을 만든 쪽이 정답까지 붙이면 점수가 부풉니다.

### 문제 해결

**어떻게 실행했나.**
- 평가용 리뷰를 별점마다 50건씩 무작위로 뽑고, 리뷰마다 절을 최대 2개 골라 **337개 절**을 만들었습니다.
- 라벨링 후보 추출(`voclens label prepare`)은 모델이 헷갈리는 절부터 고르지만, 평가 세트는 **무작위**로 뽑았습니다. 그래야 정확도가 편향되지 않습니다.

**어떤 노력을 했나: 라벨을 누가 어떻게 붙였나 (중요)**
- 정답 라벨은 **Claude 에이전트 두 개가 따로** 붙였습니다(라벨러 A·B). 사람 라벨이 아닙니다.
- 두 라벨러는 분류 규칙(정규식)과 모델 예측을 보지 못하게 했습니다. 본 것은 [라벨링 기준서](../labeling/guidelines.md)와 정규식 없는 [유형 정의](../labeling/label_definitions_product.md)뿐입니다.
- 두 라벨러의 일치도는 macro κ 0.96, "불만이 있나" 이진 κ 0.99입니다. 다만 **같은 모델을 두 번 돌린 것이라 사람 둘보다 높게 나옵니다.** 라벨이 일관적이라는 뜻이지, 정답이 맞다는 보장은 아닙니다.
- 확신이 없는 절은 보류로 표시했습니다(A 53개, B 49개). 아래 표는 보류를 뺀 값입니다.
- 라벨러 B를 정답으로 바꿔도 결론이 같은지 함께 쟀습니다.
- 라벨(절 ID와 유형만, 원문 없음): `labeling/eval/naver_shopping_eval_labels_A.json`, `_B.json`

### 결과 검토

**결과 (라벨러 A 기준, 보류 제외 284개 절 중 불만 절 88개)**

| 지표 | v0.2.1 | v0.3.0 |
|---|---|---|
| 불만 여부 정밀도 | 0.58 | **0.80** |
| 불만 여부 재현율 | 0.08 | **0.32** |
| 불만 여부 F1 | 0.14 | **0.46** |
| 불만 유형 micro F1 | 0.13 | **0.41** |
| 불만 유형 macro F1 | 0.12 | **0.37** |

라벨러 B를 정답으로 써도 v0.3.0은 불만 여부 F1 0.47, micro F1 0.40으로 거의 같습니다. 보류까지 넣으면(337개) 불만 여부 정밀도 0.84, 재현율 0.29입니다.

**유형별 (v0.3.0, 라벨러 A)**

| 유형 | 정답 절 | 정밀도 | 재현율 | F1 |
|---|---|---|---|---|
| 품질·마감 | 16 | 0.80 | 0.25 | 0.38 |
| 사이즈·색상 | 13 | 0.40 | 0.15 | 0.22 |
| 맛·신선도 | 11 | 1.00 | 0.55 | 0.71 |
| 배송 지연 | 7 | 0.60 | 0.43 | 0.50 |
| 성능 | 7 | — | 0.00 | 0.00 |
| 사용 편의 | 6 | 0.50 | 0.17 | 0.25 |
| 정보 불일치 | 6 | 1.00 | 0.33 | 0.50 |
| 가격 | 5 | 0.50 | 0.20 | 0.29 |
| 포장·파손 | 5 | 0.67 | 0.40 | 0.50 |
| 오배송·누락 | 4 | — | 0.00 | 0.00 |
| 효과 없음 | 4 | — | 0.00 | 0.00 |

정답 절이 3개 이하인 유형(문의·연락, 품질 편차, 제품 불량, 냄새, 환불·취소)은 표에서 뺐습니다.

**결과**
- v0.3.0은 **잡으면 10개 중 8개는 불만이 맞지만, 불만 절 3개 중 2개는 놓칩니다.** 리뷰 단위 대리 지표(1~2점 리뷰의 35%에 유형이 붙음)와 같은 방향입니다.
- 오탐의 주된 원인
  - 단어만 보고 판단: "반품하기 귀찮아 그냥 썼다"의 '반품'을 제품 불량으로 봄
  - 주제 표현의 과대 적용: 연락 불만 문장의 '배송'을 배송 지연으로 봄
  - 앞에 오는 부정을 놓침: "부서진 것도 없어요"를 포장·파손으로 봄
  - 비슷한 유형 혼동: '비린내'를 냄새가 아니라 맛·신선도로 봄
- 놓침은 품질·마감, 사이즈·색상처럼 **표현이 다양한 유형**에 몰립니다.

**사람 검수: Claude 라벨이 사람과 얼마나 맞나 (2026-10-21)**

평가 세트 337절에서 무작위로 20절(seed 2110)을 뽑아 사람 1명(프로젝트 작성자)이 Claude 라벨을 보지 않고 같은 기준서로 라벨링했습니다. 사람 쪽 보류는 0개입니다.

| 비교 | 불만 여부 일치 | 불만 여부 κ | 둘 다 불만인 절 | 유형 완전 일치 | 유형 하나 이상 겹침 |
|---|---|---|---|---|---|
| 사람 vs 라벨러 A | 18/20 (0.90) | 0.78 | 12 | 5 | 9 |
| 사람 vs 라벨러 B | 18/20 (0.90) | 0.78 | 12 | 5 | 9 |

- A·B는 이 20절에서 라벨이 모두 같아(B만 1절을 더 보류) 결과도 같습니다. A가 보류한 2절을 빼도 불만 여부 κ는 0.77입니다.
- **불만 여부는 사람과 대체로 맞습니다.** 어긋난 2절은 모두 사람은 칭찬, Claude는 불만(가격, 사이즈·색상)으로 본 경우입니다. Claude가 불만 쪽으로 조금 더 민감합니다.
- **유형은 덜 맞습니다.** 둘 다 불만이라고 본 12절 중 유형이 완전히 같은 것은 5절입니다. 어긋난 방식은 세 가지입니다.
  - 사람이 유형을 하나 더 붙임: 사람은 사이즈·색상이나 냄새를 함께 붙였고 Claude는 하나만 붙임 (3절)
  - 다른 유형으로 봄: 사람은 사이즈·색상, Claude는 효과 없음 또는 사용 편의 (2절)
  - Claude가 보류한 절: 사람은 제품 불량+맛·신선도, Claude는 보류+품질 편차 등 (2절)
- 사람 라벨: `data/labeling/human_labels_20.json` (원문은 없지만 평가 세트 원문 페이지와 함께 만들어 커밋하지 않음). 비교 결과는 이 표가 전부입니다.

- 정답이 Claude 라벨이라, 이 수치를 "사람 기준 정확도"로 읽는 것은 제한됩니다. 사람 검수 20절로 보면 불만 여부 지표(정밀도, 재현율, F1)는 사람 기준과 크게 다르지 않을 가능성이 높지만, 유형 지표(micro, macro F1과 유형별 표)는 사람 기준으로 읽는 것이 더 제한됩니다.

## 4. 학습한 감정 모델 (2단계, 실험)

### 문제 정의

- 2절에서 감정 사전은 걸리면 맞지만 놓치는 문장이 많았고(극성 판단 39%), 3절에서 불만 절 3개 중 2개를 놓쳤습니다.
- 질문: **학습한 감정 모델로 바꾸면 놓치는 문장이 줄고, 그만큼 불만 탐지 재현율이 오르는가? 그 대가는 무엇인가?**
- 조건: PC에 GPU가 없어 CPU에서 학습할 수 있는 작은 모델이어야 했습니다.

### 문제 해결

**어떻게 실행했나.**

| 항목 | 내용 |
|---|---|
| 모델 | `monologg/koelectra-small-v3-discriminator` (1,400만 파라미터, CPU 학습) |
| 학습 | KOTE train 40,000문장, 44감정 → 6감정 다중 라벨, 2 epoch, 최대 64토큰, CPU 67분 |
| 검증 | KOTE val 5,000문장 macro F1 0.72 (`experiments/results/emotion_kote_small_training.json`) |
| 평가 | KOTE test와 쇼핑 평가 세트는 학습에 쓰지 않음 |
| 출력 | 6감정 확률 → 중립 = Π(1 − p) → 7감정 정규화 → Valence·Arousal. 분류 기준의 Valence 임계치를 그대로 쓴다 |

쇼핑 리뷰에는 분류 규칙 v0.3.0을 그대로 두고 감성 점수만 바꿔서, 차이가 감정 모델에서만 나오게 했습니다.

**어떤 노력을 했나: 정밀도를 지키려는 임계치 조정 (실패, 기록용)**

학습 모델로 재현율은 올랐지만 정밀도가 내려가서, "주제 표현 + 부정 감성" 규칙의 Valence 기준(`topic_max_valence`, 감정 사전은 0)을 조정해 정밀도를 되찾으려 했습니다. 평가 세트는 쓰지 않고 개발용 데이터에서만 골랐습니다.

| 방법 | 개발용에서 고른 값 | 평가 세트 불만 여부 (정밀도 / 재현율 / F1) |
|---|---|---|
| 조정 없음 | 0 | 0.70 / 0.44 / **0.54** |
| ① 별점 대리 지표: 5점 리뷰 불만 비율을 감정 사전 수준(5.1%)으로 묶고 1·2점 리뷰 불만 비율 최대 | −0.45 | 0.74 / 0.32 / 0.44 |
| ② 개발용 절 정답 329개(Claude 라벨러, 평가 세트와 겹치지 않음)에서 F1 최대 | +0.20 | 0.68 / 0.45 / **0.54** |

- ①은 실패했습니다. 기준을 엄격하게 하자 5점 리뷰의 오탐은 거의 줄지 않고, 1·2점 리뷰의 실제 불만을 놓쳤습니다. **"5점 리뷰의 불만 = 오탐"이라는 가정이 틀렸습니다.** 5점 리뷰에도 실제 불만 문장이 있고("배송은 늦었지만 만족"), 리뷰 단위 비율과 문장 단위 정확도는 다르게 움직입니다.
- ②의 개발용 F1은 +0.15~−0.05 구간에서 0.62로 평평했고, +0.20이 1문장 차이로 가장 높았습니다. 평가 세트에서도 조정 없음과 차이가 없었습니다.
- 결론: 이 기준값은 개선 수단이 아닙니다. 설정은 가장 단순한 0으로 둡니다.
- 개발용 정답: `labeling/dev/naver_shopping_dev_labels.json` (원문 없음). 결과: `experiments/results/topic_threshold_tuning_rating_proxy.json`, `topic_threshold_tuning_dev_gold.json`, `shopping_gold_v0.3.0_koelectra_small_tuned.json`

## 5. 불만 유형 분류기 (2단계, 약지도) 와 규칙 v0.3.1

### 문제 정의

- 3절과 4절에서 두 가지 문제가 남았습니다. 규칙은 오탐 규칙 때문에 정밀도가 깎이고, 표현이 다양한 유형(품질·마감, 사이즈·색상)은 규칙으로 잡지 못합니다.
- 유형별 정답 라벨이 많지 않아(개발용 329절) 분류기를 지도 학습만으로 만들기는 어려웠습니다.

### 문제 해결

**어떻게 실행했나 ①: 오탐 규칙 정리 (분류 기준 v0.3.1).** 개발용 절 정답(329개)에서 확인된 오탐만 고쳤습니다. '반품'만으로 제품 불량, 배송 문장의 '느려'를 성능, 기간 표현만으로 배송 지연, "분위기가 달라졌어요"를 품질 편차, "사진과 똑같아요"를 효과 없음으로 보던 규칙입니다 ([개정 이력](voc_taxonomy.md#개정-이력)). 평가 세트의 오류 사례(반품·배송 표현)를 먼저 본 상태였다는 점을 밝혀 둡니다.

**어떻게 실행했나 ②: 약지도 불만 분류기.** 규칙이 잡은 절과 5점 리뷰의 칭찬 절을 약한 정답으로 써서 분류기를 학습했습니다.

| 항목 | 내용 |
|---|---|
| 학습 데이터 | 네이버 쇼핑 개발용 리뷰 6만 건에서 약지도 라벨 25,038절. 규칙의 불만 표현이 잡은 절 11,260개(그 유형), 5점 리뷰의 칭찬 절 13,778개(불만 없음). 개발용 절 정답의 리뷰는 제외 |
| 모델 | koelectra-small, "불만 없음 + 21개 유형" 중 하나를 고르는 분류, 앞 절을 문맥으로 붙임, 3 epoch, CPU 약 50분 |
| 합치기 | 규칙 ∪ 분류기(분류기가 기준값 이상으로 낸 유형을 더함) 또는 분류기만 |
| 선택 | 개발용 절 정답에서 불만 여부 F1 최대(미리 정한 규칙). 감정 사전/학습 감정 모델 × 규칙만/합집합/분류기만 × 기준값 0.3~0.9 → **학습 감정 모델 + 규칙 ∪ 분류기 @0.9** (개발용 F1 0.71). 0.7~0.9가 0.70~0.71로 평평했고 0.9는 탐색 범위 끝 |

**어떤 노력을 했나.**
- 첫 시도는 실패했습니다. 유형마다 맞다/아니다를 따로 배우게 했더니(시그모이드 다중 라벨) 유형마다 양성이 10% 미만이라 모델이 "전부 아니다"로 쏠렸습니다(확률 0.1~0.36). 22개 중 하나 고르기와 학습률 1e-4로 바꿔 해결했습니다.
- 조합과 기준값은 개발용 정답에서만 골랐고, 평가 세트는 **마지막에 한 번만** 쟀습니다.

- 규칙 v0.3.1은 정밀도를 0.80 → 0.88로 올렸지만(오탐 정리) 재현율은 그대로입니다. 고친 것이 오탐 규칙뿐이라 예상대로입니다.
- 학습 모델 조합은 재현율을 0.32 → 0.55로 올려 F1이 가장 높습니다. 특히 규칙이 대부분 놓치던 **사이즈·색상(0.15 → 0.54)**과 가격, 품질·마감에서 늘었습니다. 대신 정밀도가 0.64로 내려갑니다.
- 배포 화면은 정밀도가 높은 규칙 v0.3.1 + 감정 사전을 씁니다. 학습 모델 조합은 "놓치지 않는 것"이 중요한 모니터링 용도로 CLI에서 씁니다.

**한계: 이 결과로 말할 수 있는 범위는 아래로 제한됩니다**
- 개발용 F1 0.71이 평가 세트에서 0.59로 내려갔습니다. 개발용에서 조합과 기준값을 고른 만큼의 낙관이 빠진 값이고, 평가 세트 숫자가 실제 기대치입니다.
- 성능, 오배송·누락, 효과 없음은 여전히 0입니다. 약지도 라벨이 규칙에서 나왔기 때문에, 규칙이 거의 못 잡는 표현은 분류기도 배우지 못합니다. 이 세 유형에 대한 탐지는 사실상 없는 것으로 봐야 합니다.
- v0.3.1은 평가 세트의 오류 사례를 먼저 본 상태에서 고쳤으므로, v0.3.1의 정밀도 0.88은 약간 낙관적일 수 있습니다.
- 기준값 0.9가 탐색 범위 끝이라, 더 높은 값이 나았을 가능성을 배제하지 못합니다.
- 정답은 3절과 같은 Claude 라벨이라 사람 기준 정확도로 읽는 것은 제한됩니다.

**앞으로 추진**
1. **0인 유형의 학습 예시를 직접 늘립니다.** 성능, 오배송·누락, 효과 없음을 개발용 리뷰에서 골라 사람(또는 Claude) 라벨을 붙이고 분류기를 다시 학습합니다.
2. 다음 학습에서는 기준값 탐색 범위를 0.95 이상까지 넓히되, 개발용 정답에서만 고릅니다.
3. 사람 검수(3절, 20절)에서 불만 여부 κ는 0.78, 유형 완전 일치는 5/12였습니다. 그래서 이 표의 불만 여부 지표는 사람 기준에 가깝게 읽을 수 있지만 유형 지표는 그렇지 않습니다. 검수가 50절로 늘면 다시 기록합니다.
4. 새 평가는 이 평가 세트를 다시 쓰지 않고, 평가용에서 새로 뽑은 세트로 합니다(이미 결과를 본 세트이기 때문).

## 6. 손으로 정한 상수의 민감도

### 문제 정의

- 지수 식의 가중치(좌절 지수의 반복 문의 0.40 등), 우선순위 식의 0.5, CES 가중치는 데이터로 학습한 값이 아니라 손으로 정한 값입니다.
- 질문: **이 상수를 다르게 정했다면 결론(지수 순위, 개선 과제 우선순위)이 바뀌는가?** 바뀐다면 결과는 상수를 정한 사람의 판단일 뿐입니다.

### 문제 해결

**어떻게 실행했나.** 상수 19개를 하나씩 ×0.5와 ×1.5로 바꾸고, 그다음 전부 동시에 ×U(0.5, 1.5)로 무작위로 바꾸기를 500번 했습니다 (seed 42, `scripts/sensitivity_constants.py`). 쇼핑 평가용 리뷰, 합성 배달 리뷰, 합성 상담 세 곳에서 순위가 얼마나 유지되는지 쟀습니다.

**어떤 노력을 했나.** 실험용으로 다시 구현한 식이 기본값에서 배포 코드(`unit_scores`, `engagement_index`, `pain_points`, `estimate_ces`)와 같은 값을 내는지 먼저 확인했습니다. 실험 코드와 배포 코드가 다르면 민감도 결과가 배포 화면에 대해 아무것도 말해 주지 않기 때문입니다.

### 결과 검토

| 실험 | 대상 | 결과 (흔든 모든 경우 중 최악) |
|---|---|---|
| A. 지수 순위 | 쇼핑 평가용 리뷰 39,807건 (단위 89,678개) | 기본값 대비 순위 Spearman: 행복 0.998, 스트레스 1.000, 부정 정서 0.9999, 좌절 0.998, 참여 0.913 |
| A. 별점 구분력 | 같은 데이터, 별점 4·5 vs 1·2 AUC | 행복 0.80 → 최저 0.799, 좌절 0.710 → 0.709. 상수를 바꿔도 구분력이 거의 그대로 |
| B. 개선 과제 우선순위 | 쇼핑 유형 18개 (리뷰 40건 이상) | 순위 Spearman 최저 0.994, 1위 그대로 100%, 상위 3개 그대로 94.4%, 4분면 바뀐 비율 0 |
| B. 개선 과제 우선순위 | 합성 배달 유형 12개 | 순위 Spearman 최저 0.972, 상위 3개 그대로 100%, 1위 그대로 91.2%, 4분면 바뀐 비율 평균 5.7% |
| C. CES 순서 | 합성 상담 4건 | Kendall τ 최저 1.0, 가장 힘든 통화와 전체 순서 그대로 100% |

**결과**
- 상수를 절반이나 1.5배로 바꿔도 순위와 과제 선정은 거의 그대로입니다. 결론을 정하는 것은 상수가 아니라 감정 점수와 불만 비중 자체입니다. 거꾸로 말하면 상수를 조정해서 결과를 좋게 만들 여지도 작습니다.
- 가장 흔들리는 것은 참여 지수(최저 0.913)입니다. 글자 수, 측면 수, 의도 세 가지 비중에 따라 순위가 조금 바뀝니다.

**한계: 이 결과로 말할 수 있는 범위는 아래로 제한됩니다**
- 이 실험은 "상수에 결론이 좌우되지 않는다"까지만 말합니다. 상수가 맞다는 뜻은 아니며, 결론의 정확도는 감정 점수와 불만 분류의 정확도(1~5절)에 달려 있습니다.
- 참여 지수의 별점 AUC는 0.44로 0.5보다 낮습니다. 불만 리뷰 쪽 참여 지수가 오히려 높다는 뜻입니다. 참여 지수는 "얼마나 공들여 말했나"이지 만족도가 아니라서 설계대로이지만, 만족 지표로 읽는 것은 제한됩니다.
- 상담 실험은 합성 4건이라 순서가 안 바뀐다는 것 이상을 말해 주지 못합니다.

**앞으로 추진**
- AI Hub 상담 음성을 받으면 실험 C(CES 순서)를 실제 통화로 다시 돌립니다.
- 참여 지수는 대시보드와 리포트에 "만족도가 아님"을 표시하고, 만족 쪽 해석은 CSAT 추정(7절)만 쓰게 합니다.

결과 파일: `experiments/results/sensitivity_constants.json`

## 7. CSAT 추정 모델을 실제 리뷰로

### 문제 정의

- 배포 화면의 CSAT 추정 모델은 합성 배달 리뷰 155건으로 학습합니다. 합성 데이터에서 맞춘 모델이 실제 리뷰에서도 쓸 만한지 알 수 없었습니다.
- 질문: **실제 리뷰로 학습하면 얼마나 맞고, 합성으로 학습한 배포 모델을 실제 리뷰에 옮기면 얼마나 틀리는가?**

### 문제 해결

**어떻게 실행했나.** 네이버 쇼핑 리뷰로 다시 학습하고 평가했습니다 (`scripts/csat_shopping.py`). 특징 13개는 배포 코드와 같은 `session_features`로 뽑았습니다.

- 학습: 개발용에서 무작위로 뽑은 리뷰 40,000건
- 평가: 평가용 전체 39,807건 (별점 1점 7,102, 2점 12,786, 4점 3,723, 5점 16,196. 실제 만족 비율 50.0%)
- 비교 기준으로 상수 모델과 Valence 하나만 쓴 회귀를 함께 돌려, 특징 13개가 실제로 더하는 것이 있는지 봤습니다.

**어떤 노력을 했나: 이 실험에서 찾은 버그.** 만족 임계값을 예측값의 분위수로 정했는데, 예측이 같은 값에 몰리면 분위수가 그 동점 값에 걸리고 `>=` 때문에 동점 전체가 만족으로 들어갔습니다. 고치기 전에는 학습 데이터에서도 실제 49.2%를 75%로 추정했습니다. 후보 임계값마다 만족 비율을 세서 실제 비율에 가장 가까운 값을 고르도록 고쳤고(`RidgeRegressor.calibrate_threshold`), 회귀 테스트를 넣었습니다. 합성 배달 데이터는 동점이 3% 미만이라 배포 화면의 임계값(3.620)과 수치는 바뀌지 않습니다.

### 결과 검토

| 모델 | MAE | Spearman | 만족 구분 AUC | 추정 만족 비율 (실제 50.0%) |
|---|---|---|---|---|
| 상수 (학습 평균) | 1.585 | — | — | — |
| Valence 하나만 쓴 회귀 | 1.109 | 0.594 | 0.854 | 42.3% |
| **쇼핑으로 학습한 릿지 (특징 13개)** | **1.055** | **0.602** | **0.858** | 42.8% |
| 합성 배달로 학습한 릿지 (배포 화면과 같은 모델) | 1.228 | 0.559 | 0.836 | **80.8%** |

**결과**
- 실제 리뷰로 학습하면 상수보다 MAE가 33% 줄고, 만족·불만을 AUC 0.86으로 가릅니다. 다만 Valence 하나만 써도 거의 같습니다(AUC 0.854). 나머지 특징 12개가 더하는 것은 작습니다.
- 합성 배달로 학습한 모델을 실제 쇼핑 리뷰에 옮기면 순서는 꽤 유지되지만(AUC 0.836), 합성 평가용에서 0.564이던 MAE가 1.228로 두 배 넘게 나빠지고 **만족 비율을 80.8%로 크게 부풀립니다.** 임계값을 합성 데이터에서 맞췄기 때문입니다.

**한계: 이 결과로 말할 수 있는 범위는 아래로 제한됩니다**
- 배포 화면의 CSAT 비율은 절댓값으로 읽는 것이 제한됩니다. 같은 데이터 안에서 비교하는 용도로만 씁니다. 상담·영상처럼 별점이 없는 채널에 옮겨 쓸 때도 같은 문제가 생길 것으로 봅니다.
- 쇼핑으로 학습해도 추정 만족 비율은 42.8%로 실제보다 7%p 낮습니다. 감정 사전이 감정 신호를 하나도 못 잡는 리뷰가 약 31%라서, 이 리뷰들은 예측이 모두 같은 값입니다. 한 덩어리라 임계값으로 나눌 수 없습니다. 감정 사전의 재현율이 CSAT 추정의 한계를 정합니다.
- 계수는 해석하지 않습니다. Valence 관련 특징(평균, 최저, peak-end, 행복)끼리 겹쳐서, 좌절 지수 계수가 양수로 나오는 등 부호가 직관과 다릅니다. "어떤 요인이 만족을 올린다"는 설명에 계수를 쓰는 것은 제한됩니다.

**앞으로 추진**
1. 학습 감정 모델(4절, 극성 판단 97%)로 특징을 뽑아 다시 학습하고, 신호 없는 리뷰가 줄면서 추정 만족 비율의 오차(7%p)가 줄어드는지 잽니다.
2. 배포 화면의 CSAT 모델을 합성 배달 대신 실제 리뷰로 학습한 모델로 바꿀지, 절댓값 대신 상대 비교만 보여 줄지 정합니다.
3. 상담·영상에는 별점이 없으므로, 만족도 라벨이 있는 상담 데이터(AI Hub 등)를 받으면 그 채널에서 임계값을 따로 맞추고 리뷰에서 옮긴 값과 비교합니다.

결과 파일: `experiments/results/csat_shopping.json`

## 8. 음성 각성 규칙: 공개 감정 음성 두 가지

### 문제 정의

- 이 프로젝트는 상담 음성의 톤(피치, 에너지, 쉼)이 텍스트만으로는 놓치는 감정의 세기를 보완한다고 가정합니다. 이 가정을 확인하려면 감정 라벨이 붙은 한국어 상담 음성이 필요합니다.
- 상담 음성 데이터(AI Hub)는 아직 승인 전입니다. 그래서 지금 확인할 수 있는 질문으로 좁혔습니다. **음향 각성 규칙(`AcousticArousalBaseline`, 피치·에너지·쉼 가중합)이 텍스트로는 가를 수 없는 각성 차이를 가르는가?**

### 문제 해결

**어떻게 실행했나.** 같은 문장을 여러 감정으로 읽은 공개 연기 음성 두 가지로 규칙을 평가했습니다 (`scripts/ser_acted_speech.py`). 문장이 같으므로 각성이 갈린다면 그것은 음성에만 있는 정보입니다.

| | RAVDESS | CREMA-D |
|---|---|---|
| 음성 | 1,440개 | 7,442개 (깨진 파일 0) |
| 배우 | 24명 (여 12) | 91명 (여 43), 나이·인종 다양 |
| 문장 | 영어 2개 | 영어 12개 |
| 각성 높음 | 분노, 공포, 기쁨, 놀람 (768) | 분노, 공포, 기쁨 (3,813) |
| 각성 낮음 | 중립, 평온, 슬픔 (480) | 중립, 슬픔 (2,358) |
| 세기 비교 | 세기 2 vs 1 (각 672) | 한 문장(IEO)의 높음 vs 낮음 (각 455) |
| 라이선스 | CC BY-NC-SA 4.0 | ODbL 1.0 |

혐오는 각성 분류가 갈려서 뺐습니다. 화자 기준선은 배포 코드의 `normalize_by_speaker`를 그대로 썼고, 상담에서 앞 30초를 기준선으로 쓰는 것과 같은 구조로 배우의 중립(·평온) 음성을 기준선으로 삼았습니다. 음성은 커밋하지 않았습니다.

**어떤 노력을 했나.**
- 지표(전체 AUC, 배우별 최저 AUC, 성별 AUC)는 실행 전에 정했고, 가중치는 바꾸지 않고 평가만 했습니다.
- RAVDESS 결과가 우연인지 보려고, 배우가 네 배 많고 처음 보는 CREMA-D로 같은 규칙을 한 번 더 평가했습니다.

- 규칙 전체 점수만 보지 않고 특징 하나씩 AUC를 재서, 어느 가중치가 성능을 깎는지 진단했습니다.

- 처음 보는 데이터(CREMA-D)에서 0.876 → 0.829로 낮아졌습니다. 배우가 많고 연기 수준이 고르지 않아서, 배우 91명 중 9명은 0.7 아래입니다.
- 화자 정규화의 효과는 데이터마다 다릅니다. 전체 AUC는 두 데이터 모두 오르지만(0.821 → 0.876, 0.813 → 0.829), CREMA-D에서는 배우별 최저가 오히려 내려갑니다(0.679 → 0.607). 배우마다 중립 음성이 12개뿐이라 기준선이 흔들리는 것으로 보입니다.

- 남성 배우에서 더 약합니다(CREMA-D 0.773, 여성 0.883).
- 점수의 절댓값은 데이터마다 다르게 움직입니다. RAVDESS는 슬픔(0.634)이 중립(0.445)보다 높게 나와 순서도 틀리고, 높은 각성 감정은 0.85~0.89에 몰립니다. CREMA-D는 중립 0.357, 슬픔 0.315, 분노 0.561로 순서는 맞습니다.

**한계: 이 결과로 말할 수 있는 범위는 아래로 제한됩니다**
- 둘 다 연기한 감정이라 실제 상담보다 과장되어 있습니다. 이 수치는 상한선이며, 실제 상담에서의 성능 근거로 쓰는 것은 제한됩니다.
- 영어 음성이라 한글 음절로 세는 말 속도(가중치 0.20)는 0으로 고정되어 검증하지 못했습니다. 한국어 음성에 그대로 옮겨 쓰는 것은 제한됩니다.
- 각성만 검증했습니다. 음성 쪽 감성(valence)은 규칙에 없고, 텍스트와 합친 융합 가중치(각성 0.7 : 0.3)도 이 데이터로는 검증할 수 없습니다. "음성이 텍스트보다 낫다"는 확인하지 못한 가정으로 남습니다.
- 쉼 비율 부호와 가중치 문제는 알고 있지만, 평가 데이터를 본 뒤라 고치지 않았습니다. 현재 가중치(acoustic-arousal-v0.1)는 잠정값입니다.
- 각성 점수는 같은 통화 안에서 비교하는 용도로만 씁니다. 통화끼리 절댓값을 비교하는 것은 제한됩니다.
- 상담 앞 30초도 발화가 적으므로, CREMA-D처럼 화자 기준선이 흔들릴 수 있습니다.

**앞으로 추진**
1. **AI Hub 상담 음성 승인 후 같은 지표로 다시 잽니다.** 각성 AUC, 화자별 최저 AUC, 성별 차이를 이 절과 같은 방식으로 내고, 말 속도 특징은 이때 처음 검증합니다.
2. **상담 데이터를 개발용과 평가용으로 나눕니다.** 개발용에서만 쉼 비율 부호와 가중치를 다시 정해 acoustic-arousal-v0.2로 올리고, 평가용에서 v0.1과 비교합니다. 평가용을 본 뒤에는 다시 고치지 않습니다.
3. **텍스트만 쓴 결과와 음성을 합친 결과를 같은 통화에서 비교합니다.** 융합이 나아지지 않으면 "음성이 텍스트보다 낫다" 가정을 버리고 융합 가중치를 낮춥니다.
4. **기준선 길이를 점검합니다.** 상담 앞 몇 초(발화 몇 개)를 기준선으로 써야 화자별 최저 AUC가 안정되는지 봅니다.

결과 파일: `experiments/results/ser_ravdess.json`, `experiments/results/ser_crema_d.json`

## 9. 영상: 실제 YouTube 영상 2편

### 문제 정의

- 영상 파이프라인은 합성 번들로만 확인한 상태였습니다. 실제 YouTube URL에서 수집부터 분석까지 끝까지 도는지, 결과가 읽을 만한지 알 수 없었습니다.
- 영상 문장에는 정답 라벨이 없어서 정확도는 잴 수 없습니다. 그래서 이 절의 목표는 **동작 점검**입니다. 끝까지 도는지, 어디서 깨지는지, 어떤 출력을 믿을 수 있는지 가립니다.

### 문제 해결

**어떻게 실행했나.** YouTube API 키를 받은 뒤, 사람이 단 한국어 자막이 있는 공개 리뷰 영상 두 편을 URL로 수집해 분석까지 돌렸습니다 (`scripts/video_real_check.py`). 성격이 다른 두 영상(16분 휴대폰 개봉기, 35분 자동차 시승기)을 골라 길이와 제품군이 바뀌어도 도는지 봤습니다. 자막·댓글 원문은 저장하지 않았습니다.

**어떤 노력을 했나: 실제 영상에서 찾아 고친 것** (평가 규칙이 아니라 입력 처리 버그라서 고쳤습니다)
- 첫 영상의 수동 자막에 영상 길이(16분 53초) 밖의 큐가 50분까지 93개 들어 있었습니다. 편집 전 버전의 자막으로 보입니다. 영상 길이를 넘는 큐를 버리고 버린 개수를 `meta.dropped_cues_after_end`에 남깁니다.
- 마침표 없는 자막은 큐를 이어 붙여 문장을 나누는데, 413초 떨어진 큐가 한 문장으로 붙었습니다. 큐 사이가 5초를 넘으면 끊습니다. 가장 긴 문장이 415초에서 28.6초로 줄었습니다.
- 영상 파이프라인에만 도메인 설정이 없어서 휴대폰 리뷰에 '배달 지연', '누락·오배송' 같은 배달 앱용 라벨이 붙었습니다. `configs/video.yaml`에 기본 도메인 `product`를 두었습니다 (번들의 `meta.domain`이 있으면 그쪽을 씁니다).
- 댓글 지수의 몰입이 두 영상 모두 100.0이었습니다. 리뷰 공식(글 길이·속성 수)을 댓글 수백 개에 적용해서 항상 상한에 걸리므로 뺐습니다. 영상 몰입(좋아요율·댓글 수·타임스탬프 댓글 비율)은 그대로이고 손으로 다시 계산한 값(18.21)과 같습니다.

### 결과 검토

| | 휴대폰 개봉기 (underKG, `dStfwAbQB0A`) | 자동차 시승기 (오토뷰, `-D9zBKMBkeU`) |
|---|---|---|
| 길이 / 조회수 | 16분 53초 / 37만 | 35분 27초 / 34만 |
| 자막 | 수동 자막 → 174문장 (영상 밖 큐 93개 버림) | 수동 자막 → 282문장 |
| 댓글 | 448개 (타임스탬프 댓글 38개) | 500개, 상한 (타임스탬프 8개) |
| 영상 유형 | 리뷰 | 리뷰 |

**결과**
- 수집은 됩니다. URL 하나에 5~6초가 걸렸고, 수동 자막과 댓글이 모두 들어왔습니다. 위 네 가지를 고친 뒤 두 영상 모두 분석까지 끝까지 돕니다.
- 댓글에서 뽑힌 속성은 영상 내용과 맞아 보입니다. 엑시노스 칩 논란이 있던 휴대폰은 성능과 가격, 신형 그랜저는 가격이 압도적입니다.
- **크리에이터 문장의 감성은 대부분 0입니다** (82~89%). 감정 사전이 리뷰 글 위주라 말로 하는 설명문에서는 거의 반응하지 않습니다.
- **내용 구간 분할은 실제 영상에서 쓸 수 없는 수준입니다.** 도입이 중간에 네 번 나오고, 자동차 영상에 '언박싱'이 붙고, 총평이 한 번도 없거나 세 번 나옵니다. 합성 번들에서는 잘 나왔지만 실제 자막은 그렇게 정돈되어 있지 않습니다.

**한계: 이 결과로 말할 수 있는 범위는 아래로 제한됩니다**
- 정답 라벨이 없으므로 영상 채널의 정확도 수치는 없습니다. "끝까지 돈다"까지만 말할 수 있습니다.
- 크리에이터 감성 곡선과 '크리에이터 vs 시청자' 비교(차이 0.01, 0.05)는 대부분이 0인 값 위에서 나온 것이라 해석이 제한됩니다.
- 내용 구간과 총평 구간 가중 감성(`weighted_valence`)은 실제 영상에서 사용이 제한됩니다.
- 댓글 속성이 영상 내용과 맞는다는 판단은 결과를 읽고 내린 판단이고, 사람이 라벨로 확인한 것은 아닙니다. 참고용으로 제한됩니다.
- 감성 0 비율과 구간 분할 모두, 결과를 본 뒤에 규칙을 고치지 않았습니다. 평가 세트 없이 고치면 이 두 영상에만 맞춘 규칙이 되기 때문입니다.

**앞으로 추진**
1. **영상 문장 평가 세트를 만듭니다.** 9절과 9-1절의 영상 3편 문장에 사람이 감성과 내용 구간 라벨을 붙이고, 개발용과 평가용으로 나눕니다.
2. **말 감성을 보강합니다.** 개발용 문장으로 구어체 감정 표현(예: "괜찮더라고요", "좀 아쉽네요")을 감정 사전에 더하거나, KOTE로 파인튜닝한 감정 모델을 자막에 붙여 감성 0 비율과 정확도를 v0.3.1과 비교합니다.
3. **구간 분할 규칙을 다시 만듭니다.** 키워드만 보지 않고 영상 안의 시간 위치(도입은 앞, 총평은 뒤)를 함께 쓰도록 바꾸고, 평가용 세트에서 구간 일치율을 잽니다.
4. **댓글 속성 상위를 사람이 확인합니다.** 영상마다 상위 속성의 댓글을 표본으로 뽑아 맞는 비율을 기록합니다.

### 9-1. 자막 없는 영상: STT, 화자 분리, 음향 각성

#### 문제 정의

- 리뷰 영상 상당수는 사람이 단 자막이 없습니다. 이런 영상은 STT로 문장을 만들어야 하고, 음성이 있으므로 상담과 같은 음향 각성도 붙일 수 있어야 합니다.
- 코드에는 STT(Whisper)와 화자 분리(pyannote) 경로가 있었지만 실제 영상으로 돌려 본 적이 없었습니다. 정답 전사본과 정답 화자 라벨이 없으므로 이것도 **동작 점검**입니다.

#### 문제 해결

**어떻게 실행했나.** 사람 자막이 없는 공개 리뷰 영상 한 편(게임용 무선 이어폰 리뷰, 올드게이머 우라카타, `ULoEZw889Lc`, 5분 15초, 댓글 18개)을 `--stt`로 돌렸습니다. CPU에서 Whisper medium(int8)과 pyannote `speaker-diarization-3.1`을 썼습니다. 음성은 임시 폴더에만 두었다가 분석이 끝난 뒤 지웠습니다.

**어떤 노력을 했나: 실제로 돌리면서 고친 것** (모두 입력 처리 쪽입니다)
- STT 경로는 yt-dlp의 ffmpeg 후처리로 wav를 만들었는데, 이 PC에는 ffmpeg가 없습니다. 원본 오디오를 그대로 받아 PyAV로 16kHz 모노 WAV로 바꾸게 했습니다. 이제 ffmpeg 없이도 돕니다.
- faster-whisper 1.2.1의 `decode_audio`는 PyAV 19와 맞지 않아 실패했습니다. WAV를 직접 읽어 배열로 넘깁니다.
- pyannote.audio 4.x는 `use_auth_token` 대신 `token`을 받고, 파일 경로를 주면 torchcodec(ffmpeg 필요)으로 읽습니다. 파형을 직접 넘기고, 4.x의 출력 객체에서 화자 구간을 꺼내게 했습니다. 3.x도 그대로 돌도록 두 방식을 모두 받습니다. 4.x에서 3.1 파이프라인을 불러올 때는 `pyannote/speaker-diarization-community-1`에도 이용 동의가 필요합니다.
- **영상에서는 음향 각성이 한 번도 계산되지 않고 있었습니다.** 전사가 끝나면 음성이 임시 폴더와 함께 지워졌기 때문입니다. `fetch_bundle(audio_dir=...)`로 세션을 만드는 동안만 WAV를 남기고, 파이프라인은 세션을 다 만든 뒤 지웁니다.

#### 결과 검토

| 항목 | 값 |
|---|---|
| 처리 시간 (수집 + 전사 + 화자 분리) | 771초. 영상 길이의 약 2.4배 |
| STT 세그먼트 / 문장 | 69 / 71 |
| STT 신뢰도 평균 (avg_logprob 기반) | 0.893. 0.5 미만 0개 |
| 화자 분리 결과 | 1명 (혼자 말하는 리뷰라 그럴듯함) |
| SNR / 음향 각성 붙은 문장 | 17.9dB / 71문장 전부 |
| 음향 각성 평균 (표준편차) | 0.50 (0.23) |
| 말–톤 불일치 표시 | 3문장 |
| 감성 0인 문장 (크리에이터 / 댓글) | 78.9% / 33.3% |
| 내용 구간 | 15개 (사용 8번, 본문 4번, 장단점 2번, 언박싱 1번. 도입·총평 0번) |

**결과**
- 자막 없는 영상도 이제 끝까지 돌고, 음향 각성이 71문장 전부에 붙습니다. 영상 채널에서 음성 정보가 실제로 쓰인 첫 결과입니다.
- 음향 각성 평균이 0.50인 것은 화자 기준으로 정규화했기 때문에 당연한 값입니다. 문장 사이의 변화(표준편차 0.23)와 말–톤 불일치 3문장은 보입니다.
- STT 문장은 9절의 수동 자막보다 감성 0 비율이 조금 낮지만(78.9%), 여전히 대부분이 0입니다. 내용 구간도 도입과 총평이 한 번도 나오지 않아서 9절과 같은 문제가 있습니다.

**한계: 이 결과로 말할 수 있는 범위는 아래로 제한됩니다**
- CPU에서는 5분 영상에 13분이 걸립니다. 긴 영상(30분 이상)을 이 설정으로 돌리는 것은 제한됩니다.
- STT 신뢰도는 모델이 스스로 매긴 값이지 실제 오류율이 아닙니다. 사람 전사본과 비교한 문자 오류율(CER)은 재지 못했으므로, 전사 정확도에 대한 주장은 제한됩니다.
- 화자 분리는 혼자 말하는 영상 한 편에서 1명이 나온 것만 확인했습니다. 화자가 둘 이상인 영상에서 맞게 나누는지는 확인하지 못했습니다.
- 음향 각성의 문장별 변화가 맞는지는 8절의 연기 음성 결과로만 짐작할 수 있습니다. 말–톤 불일치 3문장도 사람이 확인하지 않았습니다.
- 이어폰 리뷰인데 크리에이터 문장 두 개에 속성 '맛'이 붙었습니다. 속성 추출에 도메인 필터가 없기 때문입니다. 결과를 본 뒤라서 고치지 않고 기록만 해 두며, 제품 영상의 속성 결과는 이 오류를 감안해 읽어야 합니다.

**앞으로 추진**
1. **처리 시간을 줄입니다.** 같은 영상을 Colab GPU(Whisper large-v3)와 CPU 작은 모델(small)로 돌려 처리 시간과 STT 신뢰도를 medium과 비교하고, 기본 설정을 정합니다.
2. **CER을 잽니다.** 이 영상의 일부 구간(예: 1~2분)을 사람이 받아 적고 Whisper 결과와 비교해 문자 오류율을 기록합니다.
3. **화자 분리를 확인합니다.** 두 사람이 대화하는 리뷰 영상 한 편으로 화자 수와 화자 비율이 맞는지 봅니다.
4. **속성 추출에 도메인 필터를 넣습니다.** `product` 도메인에서는 음식 속성(맛 등)을 빼는 설정을 새 버전으로 두고, 이 영상이 아닌 새 영상으로 효과를 확인합니다.
5. 말 감성과 구간 분할은 9절의 추진 과정을 그대로 따릅니다.

# 실제 데이터 평가

VoC Lens의 감정·불만 분류는 사전·규칙 기반 기준선입니다. 합성 데이터로는 "의도한 패턴을 찾는지"만 보여 줄 수 있어서, 공개된 실제 한국어 데이터로 **어디까지 맞고 어디서 놓치는지**를 쟀습니다.

## 데이터

| 데이터 | 규모 | 라벨 | 라이선스 | 용도 |
|---|---|---|---|---|
| [네이버 쇼핑 리뷰](https://github.com/bab2min/corpus) | 20만 건 (2020년 6~7월) | 별점 1·2·4·5 | Public Domain | 불만 유형 분류, 케이스 4 |
| [KOTE](https://github.com/searle-j/KOTE) | 댓글 5만 문장 (평가에는 test 5천 문장) | 44개 감정, 문장당 5명 | MIT | 감정 사전 |

- 원문은 저장소에 넣지 않습니다. `python scripts/fetch_public_data.py`로 `data/external/`에 내려받습니다 (`.gitignore` 대상). 저장소에는 원문 없는 지표 JSON(`experiments/results/`)만 둡니다.
- 네이버 쇼핑 리뷰 앞의 "재구매"는 고객이 쓴 말이 아니라 재구매 고객 표시입니다. 떼어서 `repeat_buyer` 열로 옮깁니다. 그대로 두면 재구매 의향 신호로 잘못 셉니다.

## 규칙을 고친 데이터와 평가한 데이터를 나눴다

규칙을 보고 고친 데이터로 정확도를 재면 점수가 부풀려집니다. 그래서 네이버 쇼핑 리뷰를 줄 번호 해시로 나눴습니다 (`voclens.evaluation.split_of`).

| 구분 | 비율 | 쓰임 |
|---|---|---|
| 개발용 | 80% (약 16만 건) | 놓친 리뷰를 읽고 분류 기준을 고친다 |
| 평가용 | 20% (39,807건) | 지표 계산, 라벨링 평가 세트, 케이스 4. 규칙을 고칠 때 보지 않는다 |

## 1. 불만 유형: 별점을 대리 정답으로

정답 라벨이 없어도 별점으로 방향은 확인할 수 있습니다. 1~2점 리뷰라면 불만이 있을 가능성이 높으니, 거기에 불만 유형이 붙지 않으면 놓친 것입니다.

**평가용 39,807건, 분류 기준 v0.2.1 → v0.3.0**

| 지표 | v0.2.1 | v0.3.0 |
|---|---|---|
| 불만 유형이 붙은 1점 리뷰 | 17.1% | **36.9%** |
| 불만 유형이 붙은 2점 리뷰 | 13.9% | **33.9%** |
| 불만 유형이 붙은 4점 리뷰 | 3.6% | 9.4% |
| 불만 유형이 붙은 5점 리뷰 | 1.9% | 5.1% |
| 리뷰 평균 Valence로 4~5점과 1~2점을 가르는 AUC | 0.845 | 0.856 |

- v0.2.1의 제품 도메인은 영상 리뷰용(불량·성능·배터리·사용 편의)이라 온라인 쇼핑 불만을 대부분 놓쳤습니다. 개발용 리뷰를 읽고 10개 유형을 추가했습니다 ([분류 기준 개정 이력](voc_taxonomy.md#개정-이력)).
- 4~5점 리뷰에 붙는 비율도 늘었습니다. "배송이 늦었지만 괜찮아요"처럼 고득점 리뷰에도 실제 불만이 있어서 전부 오탐은 아닙니다. 아래 3번 평가 세트에서 불만 여부 정밀도는 0.80입니다.
- 그래도 1~2점 리뷰의 약 65%는 유형이 붙지 않습니다. 그중 15.7%는 "별로예요", "실망입니다"처럼 부정적이지만 이유가 없는 리뷰(분류 불가)이고, 나머지는 사전에 없는 표현이라 놓친 것입니다. **규칙 기반의 한계이고, 파인튜닝 모델로 넘어가는 이유입니다.**

결과 파일: `experiments/results/shopping_test_ratings_v0.2.1.json`, `shopping_test_ratings_v0.3.0.json`

## 2. 감정 사전: KOTE

**KOTE test 5,000문장, 감정 사전 v0.1 (고치지 않은 상태)**

| 지표 | 값 |
|---|---|
| 감정 표현이 하나라도 걸린 문장 | 43.7% |
| 극성 AUC (긍정만 / 부정만 고른 문장 3,465개) | 0.71 |
| 극성을 판단한 비율 (\|Valence\| ≥ 0.05) | 39.4% |
| 판단했을 때 극성 정확도 | 72.5% (긍정 91.2%, **부정 56.5%**) |
| 감정 6종 macro F1 | 0.16 |

| 감정 | 정밀도 | 재현율 |
|---|---|---|
| 기쁨 | 0.77 | 0.42 |
| 슬픔 | 0.82 | 0.12 |
| 분노 | 0.92 | 0.06 |
| 불안 | 0.82 | 0.03 |
| 혐오 | 0.63 | 0.01 |
| 놀람 | 0.67 | 0.02 |

**읽는 법**
- 사전에 걸리면 대체로 맞지만(정밀도 0.6~0.9), 걸리는 경우가 적습니다(재현율 0.01~0.42). 특히 부정 감정은 표현이 다양해서 많이 놓치고, 부정 문장의 극성 정확도가 56.5%에 그칩니다.
- KOTE는 뉴스·커뮤니티 댓글이 많아서 리뷰와 표현이 다릅니다. 리뷰 데이터(위 1번)에서는 AUC가 0.856으로 더 높습니다.
- KOTE 라벨은 5명 중 **1명 이상**이 고른 감정의 합집합입니다(문장당 평균 7.9개). 그래서 감정별 정밀도는 후하게, 재현율은 박하게 나옵니다. 극성 평가는 아무도 반대 극성 감정을 고르지 않은 문장만 써서 이 영향을 줄였습니다.
- KOTE train 4만 문장은 2단계 파인튜닝에 그대로 쓸 수 있습니다. 같은 test 5천 문장으로 기준선과 비교합니다.

KOTE 44감정은 VoC Lens 7감정으로 묶어 비교합니다 (`voclens.evaluation.KOTE_TO_EMOTION`). 깨달음·비장함처럼 대응이 애매한 감정은 감정별 평가에서 뺍니다.

결과 파일: `experiments/results/kote_test_lexicon.json`

## 3. 불만 유형: 라벨링한 평가 세트

별점은 "불만이 있을 것 같다"는 대리 지표일 뿐이라, 유형이 맞는지는 절마다 붙인 정답으로 재야 합니다.

**평가 세트**
- 평가용 리뷰를 별점마다 50건씩 무작위로 뽑고, 리뷰마다 절을 최대 2개 골라 **337개 절**을 만들었습니다.
- 라벨링 후보 추출(`voclens label prepare`)은 모델이 헷갈리는 절부터 고르지만, 평가 세트는 **무작위**입니다. 그래야 정확도가 편향되지 않습니다.

**라벨은 누가 붙였나 (중요)**
- 정답 라벨은 **Claude 에이전트 두 개가 따로** 붙였습니다(라벨러 A·B). 사람 라벨이 아닙니다.
- 두 라벨러는 분류 규칙(정규식)과 모델 예측을 보지 못하게 했습니다. 본 것은 [라벨링 기준서](../labeling/guidelines.md)와 정규식 없는 [유형 정의](../labeling/label_definitions_product.md)뿐입니다. 규칙을 만든 쪽이 정답까지 붙이면 점수가 부풀기 때문입니다.
- 두 라벨러의 일치도는 macro κ 0.96, "불만이 있나" 이진 κ 0.99입니다. 다만 **같은 모델을 두 번 돌린 것이라 사람 둘보다 높게 나옵니다.** 라벨이 일관적이라는 뜻이지, 정답이 맞다는 보장은 아닙니다.
- 확신이 없는 절은 보류로 표시했습니다(A 53개, B 49개). 아래 표는 보류를 뺀 값입니다.
- 사람이 일부(예: 50개)를 다시 라벨링해 Claude 라벨과의 일치도를 재는 것이 다음 검증 단계입니다.
- 라벨(절 ID와 유형만, 원문 없음): `labeling/eval/naver_shopping_eval_labels_A.json`, `_B.json`

**결과 (라벨러 A 기준, 보류 제외 284개 절 중 불만 절 88개)**

| 지표 | v0.2.1 | v0.3.0 |
|---|---|---|
| 불만 여부 정밀도 | 0.58 | **0.80** |
| 불만 여부 재현율 | 0.08 | **0.32** |
| 불만 여부 F1 | 0.14 | **0.46** |
| 불만 유형 micro F1 | 0.13 | **0.41** |
| 불만 유형 macro F1 | 0.12 | **0.37** |

라벨러 B를 정답으로 써도 v0.3.0은 불만 여부 F1 0.47, micro F1 0.40으로 거의 같습니다. 보류까지 넣으면(337개) 불만 여부 정밀도 0.84, 재현율 0.29입니다.

**유형별 (v0.3.0, 라벨러 A)**

| 유형 | 정답 절 | 정밀도 | 재현율 | F1 |
|---|---|---|---|---|
| 품질·마감 | 16 | 0.80 | 0.25 | 0.38 |
| 사이즈·색상 | 13 | 0.40 | 0.15 | 0.22 |
| 맛·신선도 | 11 | 1.00 | 0.55 | 0.71 |
| 배송 지연 | 7 | 0.60 | 0.43 | 0.50 |
| 성능 | 7 | — | 0.00 | 0.00 |
| 사용 편의 | 6 | 0.50 | 0.17 | 0.25 |
| 정보 불일치 | 6 | 1.00 | 0.33 | 0.50 |
| 가격 | 5 | 0.50 | 0.20 | 0.29 |
| 포장·파손 | 5 | 0.67 | 0.40 | 0.50 |
| 오배송·누락 | 4 | — | 0.00 | 0.00 |
| 효과 없음 | 4 | — | 0.00 | 0.00 |

정답 절이 3개 이하인 유형(문의·연락, 품질 편차, 제품 불량, 냄새, 환불·취소)은 표에서 뺐습니다. 표본이 작아 유형별 수치는 ±0.2 이상 흔들릴 수 있습니다.

**읽는 법**
- v0.3.0은 **잡으면 10개 중 8개는 불만이 맞지만, 불만 절 3개 중 2개는 놓칩니다.** 리뷰 단위 대리 지표(1~2점 리뷰의 35%에 유형이 붙음)와 같은 방향입니다.
- 오탐의 주된 원인
  - 단어만 보고 판단: "반품하기 귀찮아 그냥 썼다"의 '반품'을 제품 불량으로 봄
  - 주제 표현의 과대 적용: 연락 불만 문장의 '배송'을 배송 지연으로 봄
  - 앞에 오는 부정을 놓침: "부서진 것도 없어요"를 포장·파손으로 봄
  - 비슷한 유형 혼동: '비린내'를 냄새가 아니라 맛·신선도로 봄
- 놓침은 품질·마감, 사이즈·색상처럼 **표현이 다양한 유형**에 몰립니다. 규칙을 더 늘리기보다 학습 모델이 필요한 부분입니다.
- 이 오류들을 보고 규칙을 고치지 않았습니다. 평가 세트를 보고 규칙을 고치면 이 점수를 더는 믿을 수 없게 됩니다. 고칠 때는 개발용 데이터에서 같은 유형의 오류를 찾아 고치고, 평가 세트로 다시 잽니다.

결과 파일: `experiments/results/shopping_gold_v0.2.1.json`, `shopping_gold_v0.3.0.json`, `shopping_gold_v0.3.0_labeler_B.json`

```bash
voclens eval gold labeling/eval/naver_shopping_eval_labels_A.json --out experiments/results/shopping_gold_v0.3.0.json
git show 3516934:configs/taxonomy.yaml > taxonomy_v0.2.1.yaml
voclens eval gold labeling/eval/naver_shopping_eval_labels_A.json --taxonomy taxonomy_v0.2.1.yaml
```

## 다시 만들기

```bash
python scripts/fetch_public_data.py
voclens eval kote data/external/kote/test.tsv --out experiments/results/kote_test_lexicon.json
voclens eval ratings data/external/naver_shopping/naver_shopping.txt --split test --out experiments/results/shopping_test_ratings_v0.3.0.json
```

수치는 2026-10-16 기준 코드(감정 사전 v0.1, 분류 기준 v0.3.0)로 만든 값입니다. 평가 세트를 만든 뒤에는 분류 규칙을 바꾸지 않았습니다.
